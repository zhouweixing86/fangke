## 1. 联调目标

跑完本指南应确认以下 6 件事，任何一项不成立都会影响业务方案：

| 序号 | 目标 | 对应业务规则 |
|---|---|---|
| 1 | 平台能登录设备并读到设备参数 | — |
| 2 | **设备每 30 秒把心跳推到平台配置的地址** | — |
| 3 | 设备识别后能把通行记录推到平台，平台回 `ok` 后不再重推 | BR-V-009、BR-V-012、BR-V-025 |
| 4 | 平台下发白名单后，凭**身份证号**即可开门（不需要照片） | BR-V-001、W0 V1 |
| 5 | 平台在线比对接口能对**动态二维码**实时放行/拒绝 | BR-V-018~BR-V-024、W0 V6 |
| 6 | 入口/出口两台设备的 `inout` 方向正确，上报记录方向可靠 | BR-V-026、W0 V8 |

| 项目 | 说明 |
|---|---|

## 3. 操作步骤

> 仓库已提供两个辅助脚本，3.0~3.6 大部分步骤可用一条命令完成：
> - [tools/device-probe.ps1](../tools/device-probe.ps1)：`-Action login|params|version|heartbeat|callback|open|all`
> - [tools/heartbeat-receiver.py](../tools/heartbeat-receiver.py)：接收心跳与通行记录并自动回 `ok`
>
> 下面同时给出“脚本”与“手写调用”两种写法，便于排查时对照。

### 3.0 确认网络连通

```powershell
$dev = '192.168.1.135'          # 改成设备实际 IP
Test-Connection -ComputerName $dev -Count 2
Test-NetConnection -ComputerName $dev -Port 8091
```

调用接口统一用 `Invoke-RestMethod`（避免 JSON 引号转义问题）：

```powershell
$dev = '192.168.1.135'
$r = Invoke-RestMethod -Uri "http://$dev:8091/deviceLogin" -Method Post `
     -ContentType 'application/json' -Body (@{ password = '123456' } | ConvertTo-Json)
$r | ConvertTo-Json
```

预期返回：

```json
{"message": "Login Success", "result": 0}
```

> 无 PowerShell 的机器（或抓包时）等价的 curl：
> `curl.exe -s -X POST "http://192.168.1.135:8091/deviceLogin" -H "Content-Type: application/json" --data-raw "{\"password\":\"123456\"}"`

| 现象 | 原因 |
|---|---|
| 连接被拒绝 / 超时 | IP 不通、不在同网段、设备未开机 |
| `result: 2` | 密码错误（设备被改过密码） |
| HTTP 200 但内容不是 JSON | 端口被其它服务占用 |

#### 3.0.1 没有交换机时：一根网线直连笔记本

现场通常没有交换机，**普通网线直连笔记本网口即可**（设备与笔记本都支持端口自动翻转，不需要交叉线）：

1. 网线一头插设备网口，一头插笔记本网口。
2. 笔记本「有线网卡」设为手动 IP，与设备同网段，例如：

```powershell
# 先看笔记本自己的网卡序号与名称
Get-NetAdapter | Format-Table Name, InterfaceDescription, InterfaceIndex, Status

# 把有线网卡设为 192.168.1.50/24（需管理员权限；Index 换成上一步看到的序号）
New-NetIPAddress -InterfaceIndex 24 -IPAddress 192.168.1.50 -PrefixLength 24
```

> **先看笔记本现有 IP，避免网段冲突**：
> ```powershell
> Get-NetIPAddress -AddressFamily IPv4 | Where-Object IPAddress -notlike '127.*' |
>     Select-Object InterfaceAlias, IPAddress, PrefixLength
> ```
> 如果笔记本 WiFi 已经是 `192.168.1.x`，有线也设成 `192.168.1.x` 就会冲突（同一个网段有两张网卡，访问设备时可能走错网卡）。这种情况下**换一个网段**，例如有线设 `192.168.10.50/24`，设备设 `192.168.10.135`，两者都在 `192.168.10.x` 即可。

3. 设备侧在「有线网络」里确认状态变为**已连接**，记下它的 IP；若设备是 DHCP 且拿不到地址，到有线网络页手动给设备设 `192.168.1.135`（与笔记本同段、不同地址）。

> **直连时没有 DHCP 服务器**：如果设备有线网络是「自动获取」，直连笔记本会一直拿不到 IP。两种解法——① 先接路由器/交换机让它拿到地址；② 在设备界面把有线改成静态 `192.168.1.135 / 255.255.255.0`。这一步是直连最容易卡住的地方。
>
> 另外：笔记本若没有 RJ45 网口（轻薄本），需要一个 **USB 转网口**适配器；设备本身要单独供电。

4. 回到 3.0 用 `Test-NetConnection` 验证 8091 端口。
5. 调试完把笔记本网卡改回自动获取：

```powershell
Remove-NetIPAddress -InterfaceIndex 24 -IPAddress 192.168.1.50 -Confirm:$false
```

> 若设备既不是 DHCP 也不允许改静态 IP，可用 `arp -a` 或厂家扫描工具找设备地址。

### 3.1 读取设备参数（建立基线）

```powershell
$r = Invoke-RestMethod -Uri "http://$dev:8091/getDeviceParameter" -Method Post `
     -ContentType 'application/json' -Body (@{ password = '123456' } | ConvertTo-Json)
$r.data | ConvertTo-Json -Depth 5
```

需要记录并核对的关键字段：

| 字段 | 含义 | 本项目期望值 |
|---|---|---|
| `inout` | 0 出口 / 1 入口 | 入口机 = 1，出口机 = 0 |
| `recogModeID` | 1 人证比对、2 人证+白名单、3 仅刷身份证、4 验证身份证（按证件号查白名单） | 4（证明白名单按证件号命中，访客无需人脸） |
| `Comparison` | 0 离线比对 / 1 在线比对 | 二维码场景需 1 |
| `comparisonAddress` | 在线比对地址 | 平台在线比对接口 URL |
| `recogSpaceTime` | 识别去重时间（秒） | ≥ 2，对应 BR-V-016 |
| `recogRelay` | 0 继电器不输出 / 1 输出 | 1；若设 0 必须靠平台调 `/setDeviceRemoteOpen` 开门 |
| `whitevalue` / `mapvalue` | 人脸阈值 / 人证阈值 | 按现场光照调整，先记录默认值 |

> 建议把整段返回 JSON 存档，作为“设备出厂基线”，后续改参数出问题可对照回滚。

### 3.2 配置心跳 IP（设备 → 平台）

**第一步：在平台侧起一个临时接收端**，把收到的报文原样打印出来（仓库已提供，无需依赖）：

```powershell
python .\tools\heartbeat-receiver.py 18080     # 默认就是 18080
```

它会监听 `0.0.0.0:18080`，对每个 POST 打印格式化后的 JSON，并回 `{"message":"ok","result":0}`。想换端口就加参数，例如 `python .\tools\heartbeat-receiver.py 9001`。

> 端口请选一个**未被占用**且防火墙已放行的端口（Windows 上 9000 常被其它服务占用）。

**第二步：下发心跳配置**（`heartBeatEnable`：**0 开、1 关**）

用脚本一条命令完成（参数含义见 `tools/device-probe.ps1` 头部注释）：

```powershell
.\tools\device-probe.ps1 -Device 192.168.1.135 -Action heartbeat -PlatformIp 192.168.1.50
```

等价的手写调用：

```powershell
$body = @{
    password = '123456'
    data     = @{ heartBeatEnable = 0; heartBeatIp = 'http://<平台IP>:18080/heartBeat' }
} | ConvertTo-Json -Depth 5

Invoke-RestMethod -Uri "http://$dev:8091/setDeviceParameter" -Method Post `
    -ContentType 'application/json' -Body $body
```

**第三步：验证**

- 接收端每 **30 秒**打印一条 POST，body 含 `currentTime`、`ip`、`personCount`（人脸数）、`SN`。
- 平台必须回 `{"message":"ok","result":0}`。
- 30 秒内没有任何请求：核对设备网络、`heartBeatEnable` 取值（0 才是开）、平台防火墙、`heartBeatIp` 是否要求纯 IP。

**备选（平台主动查询设备心跳）**：

```powershell
$body = @{ password = '123456'; ip = $dev } | ConvertTo-Json
Invoke-RestMethod -Uri "http://$dev:8091/heartBeat" -Method Post `
    -ContentType 'application/json' -Body $body
```

### 3.3 配置通行记录回调（设备 → 平台）

```powershell
$body = @{
    password       = '123456'
    platformEnable = 0                                  # 0 = 开，1 = 关
    platformIp     = 'http://<平台IP>:18080/getrecord/'
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://$dev:8091/setIdentifyCallBck" -Method Post `
    -ContentType 'application/json' -Body $body
```

> `setIdentifyCallBck` 中 **`platformEnable=0` 为开**（与 `setDeviceParameter` 中 `1 为开`相反），这是最容易配错的一处。

验证：刷一次身份证，接收端应收到一条记录，且必须回 `{"message":"ok","result":0}`；否则设备会**一直重推同一条**。重点核对字段：`inout`、`IdentifyType`、`resultStatus`、`employee_number`、`idNum`、`time`、`face_base64`。

### 3.4 下发名单验证（访客无照片 / 员工带照片）

访客（不需要照片，`passAlgo: true`）：

```powershell
$body = @{
    password   = '123456'
    totalnum   = 1
    currentnum = 1
    data       = @{
        usertype        = 'visitor'
        employee_number = 'V0001'
        name            = '测试访客'
        idno            = '431024199522140067'
        peoplestartdate = '2026-11-16 '     # 注意末尾的空格
        peopleenddate   = '2026-11-16 '
        passAlgo        = $true             # true = 不需要照片
        TimeGroupId     = 0
    }
} | ConvertTo-Json -Depth 5

Invoke-RestMethod -Uri "http://$dev:8091/addDeviceWhiteList" -Method Post `
    -ContentType 'application/json' -Body $body
```

要点：

1. 日期格式 `yyyy-MM-dd`，**后面带一个空格**（原文要求），否则可能解析失败。
2. `passAlgo: true` = 不需要照片，访客不采集人脸即可通行。
3. 用该身份证刷卡 → 应开门；用未下发的身份证刷卡 → 不应开门（即 W0 V1 的结论）。
4. 撤销：`/deleteDeviceWhiteList`（`data.employee_number` + `data.usertype`）；清空：`/deleteDeviceAllWhiteList`。
5. 员工（带照片）：同一接口，`passAlgo: false` + `register_base64`（照片 ≤ 500KB、≥ 400×400）。

### 3.5 在线比对（动态二维码 / 人证）联调

设备侧：`Comparison=1`，`comparisonAddress` 指向平台的在线比对接口（协议见 06 文档「3.0 在线比对识别」）。

设备请求关键字段：`dev_sno`、`type`（`qr` / `id` / `face` / `ic`）、`value`（二维码内容 / 身份证号）、`data.capture`（抓拍，扫码无照片）、`time`。

平台返回：

```json
{ "status": 0, "msg": "识别成功", "audio": "识别成功" }
```

- `status=0` 开门，非 0 不开门；`msg` 与 `audio` 会显示/播报到设备上。
- 动态二维码 60 秒有效、可重复使用、由平台实时校验（BR-V-019、BR-V-020、BR-V-022）。
- 必须同时验证：**开启在线模式后，刷身份证 / 刷脸是否仍正常**（W0 V6 的关键结论）。

### 3.6 远程开门与兜底

```powershell
Invoke-RestMethod -Uri "http://$dev:8091/setDeviceRemoteOpen" -Method Post `
    -ContentType 'application/json' -Body (@{ password = '123456' } | ConvertTo-Json)
```

用于：员工刷脸失败后保安人工核实开门（BR-V-003）、出口设备识别失败时的异常离场放行（BR-V-030）。

### 3.7 断网行为确认

1. 拔掉设备网线（设备仍通电）：已下发的名单仍可开门（BR-V-013）。
2. 断网期间：新增授权无法下发（BR-V-014），动态二维码不可用（BR-V-022）。
3. 恢复网络后：确认离线期间的通行记录被补推（记录支持断网续传），且撤销的授权失效（BR-V-015）。

## 4. 排错速查

| 现象 | 排查方向 |
|---|---|
| 所有接口都连不上 | 设备 IP 变了、网线/交换机、PC 与设备不同网段 |
| `result: 2` | `password` 不是设备当前密码 |
| `result: 1` | 参数名/类型不符，或日期格式错误（缺尾随空格） |
| 心跳收不到 | `heartBeatEnable` 取值反了（0 开 1 关）、地址不可达、平台防火墙 |
| 记录反复重推 | 平台没回 `{"message":"ok","result":0}` |
| 刷证不开门 | `recogModeID` 不是 4、名单未下发成功、有效期过期、`TimeGroupId` 限制 |
| 二维码放行不了 | `Comparison` 未设为 1、`comparisonAddress` 不可达、返回 `status` 非 0 |
| 进出方向记错 | 两台设备 `inout` 配置相同 |

## 7. 网络形态决定“心跳 IP”填什么

心跳 IP 不是设备自己的地址，而是**设备要主动上报的那台服务器地址**：设备每 30 秒把 `currentTime / ip / personCount / SN` POST 过去。所以这个地址必须是**从设备所在网络能访问到**的地址。

| 设备联网方式 | 平台能否主动访问设备（8091） | 心跳 IP 填什么 | 结论 |
|---|---|---|---|
| 有线接入现场内网 | 能 | 平台**内网 IP** + 端口 | ✅ 推荐，本指南默认方案 |
| WiFi 接入现场内网 | 能 | 平台**内网 IP** + 端口 | ✅ 同上 |
| 仅 4G/蜂窝 | **不能**（运营商 NAT，设备无固定公网地址） | 平台**公网 IP 或域名** + 已放行端口 | ⚠ 只能“设备→平台”单向通信 |
| 4G + 内网穿透（frp 等） | 不能直连 | 穿透映射后的公网地址 + 端口 | ⚠ 仅调试可用，不适合生产 |

> **4G 机型看不到“IP 地址”是正常的**：那是运营商分配的私有地址，随重连变化，既不能作为设备地址，也不能从外网访问。

**仅 4G 会带来三个硬限制**（与业务规则冲突，需提前决策）：

| 限制 | 影响的业务规则 | 说明 |
|---|---|---|
| 平台无法主动下发名单 | BR-V-005、BR-V-013 | 审批通过后“授权下发到门口设备”这条路走不通，只能等设备来拉 |
| 平台无法远程开门 | BR-V-003、BR-V-030 | 保安兜底开门失效 |
| 在线比对/二维码校验依赖出网 | BR-V-022 | 设备能出网即可用，但延迟与稳定性受 4G 影响 |

**结论建议**：真实机器安装时优先**有线接入现场内网**（大门门卫室有网络），心跳 IP 填访客平台服务器的内网地址；4G 仅作为链路备份或临时调试。

**判断方法**：看设备是否有 RJ45 网口，或“网络设置”里是否有「有线/以太网」选项；把设备型号与界面截图留档到第 6 节。

### 8.1 4G 显示 0.0.0.0 / 未连接的排查顺序

按顺序做，每步做完看一次「连接状态」：

| 顺序 | 检查项 | 具体动作 |
|---|---|---|
| 1 | SIM 卡是否插入 | 断电后打开卡槽，确认卡型（Micro/Nano）、方向、是否插到底；重新插拔后再上电 |
| 2 | 流量卡是否可用 | 把卡插到手机上测：能否上网、是否欠费/未激活/被停机（物联网卡需实名与激活） |
| 3 | APN 设置 | 蜂窝数据页若可填 APN，填运营商默认值（移动 `cmnet`、联通 `3gnet`、电信 `ctnet`）；物联网卡需填卡商给的专用 APN |
| 4 | 天线 | 确认 4G 天线已接到标有 LTE/4G 的口，且拧紧 |
| 5 | 重启 | 断电 30 秒再上电，等 1~2 分钟 |
| 6 | 信号 | 换到靠窗/室外再试；界面若有信号强度（dBm/格数）记录下来 |
| 7 | 数据漫游 | 部分物联网卡需开启「数据漫游」才能注册网络 |

> 若以上都做过仍是 `0.0.0.0`，联系厂商确认该机 4G 模块与固件版本（提供 SN `T77R781116ZS`）。

### 8.2 「平台设置 → 连接三方平台」先不要改

这个下拉很可能切换的是**设备主动连平台**的模式（即云对接/MQTT，见 [07](./07-设备对接协议-RV1109云对接.md)），与本方案「平台主动调设备 8091」是两条不同的路。随意切换可能导致：

- 设备按云协议去连我们的地址，而我们没搭 MQTT，表现为「一直连不上」；
- 记录上报方式改变，局域网回调（`setIdentifyCallBck`）失效。

**处理方式**：先把下拉里的**全部选项名**记下来（截图最好），再决定；在确认之前保持现状。

### 8.3 恢复联调的最短路径

```
借一根网线
   └─ 按 3.0.1 笔记本直连设备 → 拿到设备 IP
        └─ 3.0 验证 8091 → 3.1 读参数（顺带取 /getDeviceVersion 补全固件版本）
```

### 8.4 网线到位当天：30 分钟清单

**这一步能同时拿到的结论**：W0 的 V1（按证件号匹配）、V3（有效期生效）、V5（容量/下发耗时）、V8（入口/出口方向）——因为都是本地行为，与 4G 无关。

**只有以下两项依赖 4G/外网**，可以先跳过：
- 真实机器若部署在无内网的位置，心跳要发到公网服务器（4G 场景）；

> 真实机器到场时同理：接内网 → 设备侧配心跳 IP 指向访客平台服务器内网地址 → 即接入现有访客系统，**不接厂商云**。
