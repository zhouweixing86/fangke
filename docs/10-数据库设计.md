## 1. 设计约定

### 1.1 命名与结构

| 项 | 约定 |
|---|---|
| 表名 / 字段名 | 小写下划线，单数名词（`employee`、`access_event`） |
| 主键 | `id BIGINT UNSIGNED AUTO_INCREMENT`，仅作物理主键 |
| **业务编号** | 单独字段（`person_no`、`appointment_no`），**不使用自增 ID 对外暴露**（01 文档 6.2 约定） |
| 时间 | `created_at` / `updated_at` 均 `DATETIME(3)`，应用侧写；业务时间用 `DATETIME` |
| 软删除 | 仅业务实体带 `deleted_at DATETIME NULL`；日志/事件类**不软删** |
| 操作人 | `created_by` / `updated_by BIGINT UNSIGNED`（关联 `sys_user.id`） |
| 布尔 | `TINYINT(1)`，字段名以 `is_` 开头 |
| 金额/比例 | 无；阈值类用 `SMALLINT` |
| 外键 | **不建物理外键**（便于分库与批量导入），由应用保证；所有关联字段建索引 |
| 字符集 | 表级 `utf8mb4`，避免 emoji/生僻姓名丢失 |

### 1.2 加密字段命名约定

同一业务值最多三个字段，命名固定：

| 后缀 | 类型 | 用途 |
|---|---|---|
| `_enc` | `VARBINARY(255)` | AES-256-GCM 密文（含 IV 与 tag），**唯一可信来源** |
| `_hmac` | `CHAR(64)` | HMAC-SHA256 十六进制摘要，**用于唯一索引与等值查询** |
| `_mask` | `VARCHAR(64)` | 脱敏展示值（如 `110101********1234`），列表页直接读，不解密 |

> 三者由应用在同一事务内写入，`_enc` 与 `_hmac` 不允许单独更新。

## 3. 组织与人员

```sql
CREATE TABLE dept (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  dept_code    VARCHAR(32)  NOT NULL COMMENT '部门编码',
  dept_name    VARCHAR(64)  NOT NULL,
  parent_id    BIGINT UNSIGNED NOT NULL DEFAULT 0,
  sort_no      INT NOT NULL DEFAULT 0,
  created_at   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  deleted_at   DATETIME(3) NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_dept_code (dept_code),
  KEY idx_parent (parent_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='部门';

> **部门自助维护**：管理端「部门管理」页可增删改；删除是**逻辑删除**（`deleted_at`），
> 历史员工仍能带出部门名。有员工或有子部门时拒绝删除（3004），必须先转移。
> 员工列表/表单里的 `employeeCount` 用子查询统计。

CREATE TABLE employee (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  person_no     VARCHAR(16) NOT NULL COMMENT '业务编号：E+6位工号，如 E000123',
  emp_no        VARCHAR(16) NOT NULL COMMENT '工号',
  name          VARCHAR(64) NOT NULL,
  dept_id       BIGINT UNSIGNED NULL,
  leader_id     BIGINT UNSIGNED NULL COMMENT '直属上级（默认二级审批候选）',
  title         VARCHAR(64) NULL,
  phone_enc     VARBINARY(255) NULL,
  phone_hmac    CHAR(64) NULL,
  phone_mask    VARCHAR(20) NULL COMMENT '手机号脱敏，唯一索引依据之一',
  id_card_enc   VARBINARY(255) NULL,
  id_card_hmac  CHAR(64) NULL,
  id_card_mask  VARCHAR(32) NULL,
  status        TINYINT NOT NULL DEFAULT 1 COMMENT '1在职 2待复核 3停用 4已删除',
  valid_from    DATE NULL COMMENT '通行有效期起',
  valid_to      DATE NULL COMMENT '通行有效期止（到期前15天提醒）',
  face_status   TINYINT NOT NULL DEFAULT 0 COMMENT '0无照片 1已上传 2下发中 3已生效',
  remark        VARCHAR(255) NULL,
  created_by    BIGINT UNSIGNED NULL,
  updated_by    BIGINT UNSIGNED NULL,
  created_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at    DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  deleted_at    DATETIME(3) NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uk_person_no (person_no),
  UNIQUE KEY uk_emp_no (emp_no),
  UNIQUE KEY uk_phone_hmac (phone_hmac),
  UNIQUE KEY uk_id_card_hmac (id_card_hmac),
  KEY idx_status_valid_to (status, valid_to),
  KEY idx_dept (dept_id),
  KEY idx_name (name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='员工';

CREATE TABLE employee_face (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  employee_id  BIGINT UNSIGNED NOT NULL,
  oss_key      VARCHAR(255) NOT NULL COMMENT '对象存储 key，原始上传件',
  oss_key_std  VARCHAR(255) NULL COMMENT '压缩后下发件（100~200KB）',
  width        INT NULL,
  height       INT NULL,
  size_bytes   INT NULL,
  sha256       CHAR(64) NULL COMMENT '文件指纹，防重复上传',
  is_current   TINYINT(1) NOT NULL DEFAULT 1 COMMENT '是否当前生效照片',
  uploaded_by  BIGINT UNSIGNED NULL,
  created_at   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  KEY idx_emp_current (employee_id, is_current),
  KEY idx_sha256 (sha256)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='员工人脸照片（二进制在 OSS）';
```

> **照片上传不建审核流**（C-16「上传即审核」），但替换必须新增一行并把旧行 `is_current=0`，以保留变更历史（BR-E-005）。

## 4. 门点与设备

```sql
CREATE TABLE gate (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  gate_code  VARCHAR(32) NOT NULL,
  gate_name  VARCHAR(64) NOT NULL,
  gate_type  TINYINT NOT NULL DEFAULT 1 COMMENT '1大门 2侧门 3车库门 9待分配（V11）',
  status     TINYINT NOT NULL DEFAULT 1 COMMENT '1启用 0停用',
  sort_no    INT NOT NULL DEFAULT 0 COMMENT '显示顺序，越小越前（V11）',
  remark     VARCHAR(255) NULL COMMENT '备注（V11）',
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_gate_code (gate_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='门点';
```

> **多门点（V11）**：厂区 4 个门时不能再把门点写死为 1。
> V11 额外插入系统保留门点 `UNASSIGNED / 待分配`（`gate_type=9`），
> 轮询式终端首次心跳自动登记时先落这里，避免新设备误进 1 号门；
> 该门点不参与授权（不能选、不能停用、不能改类型）。
> `appointment.gate_id` 也由 V11 增加，`NULL` 表示沿用 `fangke.gate.default-id`。

CREATE TABLE device (
  id             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  device_sn      VARCHAR(64) NOT NULL COMMENT 'SN，如 T77R781116ZS',
  mac            VARCHAR(32) NOT NULL COMMENT 'dev_sno，如 0A:0C:E8:68:11:16',
  device_name    VARCHAR(64) NOT NULL,
  model          VARCHAR(64) NULL COMMENT '如 C978GH',
  firmware       VARCHAR(128) NULL COMMENT '如 V1.11248.20260616-C978GH-DHCP',
  gate_id        BIGINT UNSIGNED NOT NULL,
  direction      TINYINT NOT NULL COMMENT '0出口 1入口，对应 inout',
  channel        VARCHAR(8) NOT NULL DEFAULT 'LAN' COMMENT 'LAN / CLOUD，双通道选择',
  ip             VARCHAR(64) NULL,
  port           INT NOT NULL DEFAULT 8091 COMMENT '已弃用（九鼎已下线，轮询式终端不用端口）',
  api_password   VARBINARY(255) NULL COMMENT '已弃用（九鼎设备口令，轮询式终端用签名 key）',
  capability     JSON NULL COMMENT '能力位：idCard/qrcode/onlineCompare/face/remoteOpen',
  online_state   TINYINT NOT NULL DEFAULT 0 COMMENT '0离线 1在线',
  last_heartbeat DATETIME(3) NULL,
  person_count   INT NULL COMMENT '心跳上报的人脸数，容量水位',
  capacity       INT NULL COMMENT '设备人员容量上限',
  status         TINYINT NOT NULL DEFAULT 1 COMMENT '1启用 0停用',
  remark         VARCHAR(255) NULL,
  created_at     DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at     DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_device_sn (device_sn),
  UNIQUE KEY uk_mac (mac),
  KEY idx_gate (gate_id),
  KEY idx_online (online_state, last_heartbeat)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='终端设备';

CREATE TABLE device_param_snapshot (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  device_id   BIGINT UNSIGNED NOT NULL,
  params      JSON NOT NULL COMMENT 'getDeviceParameter 全量回读',
  source      TINYINT NOT NULL COMMENT '1平台下发 2人工界面修改 3首次建档',
  operator_id BIGINT UNSIGNED NULL,
  created_at  DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  KEY idx_device_time (device_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='设备参数快照';

CREATE TABLE device_heartbeat (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  device_id    BIGINT UNSIGNED NOT NULL,
  device_sn    VARCHAR(64) NOT NULL,
  device_ip    VARCHAR(64) NULL,
  person_count INT NULL,
  device_time  DATETIME NULL COMMENT 'currentTime（时间戳换算）',
  clock_skew_s INT NULL COMMENT '设备时间与服务器差值，>60 告警（JOB-09）',
  raw          JSON NULL,
  created_at   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  KEY idx_device_time (device_id, created_at),
  KEY idx_created (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='设备心跳（滚动保留 7 天）';

CREATE TABLE device_cmd (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  device_id   BIGINT UNSIGNED NOT NULL,
  cmd_type    VARCHAR(32) NOT NULL COMMENT 'UPSERT_VISITOR/UPSERT_EMPLOYEE/REMOVE/OPEN_DOOR/SET_PARAMS/CLEAR_ALL/LIST',
  priority    TINYINT NOT NULL DEFAULT 1 COMMENT '0实时 1增量 2批量 3清理',
  payload     JSON NULL,
  status      TINYINT NOT NULL DEFAULT 0 COMMENT '0待执行 1执行中 2成功 3失败 4放弃',
  retry_count INT NOT NULL DEFAULT 0,
  next_run_at DATETIME(3) NULL COMMENT '指数退避下次执行时间',
  error_code  VARCHAR(16) NULL COMMENT '4001~4004，见 09 §5.5',
  error_msg   VARCHAR(512) NULL,
  batch_id    BIGINT UNSIGNED NULL COMMENT '关联 sync_batch',
  started_at  DATETIME(3) NULL,
  finished_at DATETIME(3) NULL,
  created_at  DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  KEY idx_dequeue (device_id, status, priority, next_run_at),
  KEY idx_batch (batch_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='平台→设备指令队列（串行执行）';
```

> **串行性**：同一 `device_id` 的指令必须串行。取任务用
> `SELECT ... WHERE device_id=? AND status=0 ORDER BY priority, id LIMIT 1 FOR UPDATE SKIP LOCKED`，
> 由 `DeviceGateway` 单线程执行器保证（见 09 §2.1）。

## 9. 凭证

> 实现落地为 `qr_ticket`（V8 建表 + V9 对齐 BR-V-020）。与最初设计的差异已在下方注释，均以需求为准：
> 有效期 60 秒（BR-V-019）、**有效期内可重复使用**（BR-V-020）、只存码摘要（不存明文）、校验失败留痕（BR-V-024）。

  affected    INT NOT NULL DEFAULT 0 COMMENT '处理条数',
  message     VARCHAR(500) NULL,
  PRIMARY KEY (id),
  KEY idx_code_time (job_code, started_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='定时任务执行日志（运维排查）';
```

> 原设计的 `notify_log` 已按实现改为 `notification`：站内与短信共用一张表（`channel` 区分），
> 增加 `dedup_key` 唯一索引做幂等、`retry_count` 支持失败重试、`read_at` 支持未读角标。
> 移动端只展示 `channel=1`（站内），短信记录只在管理端「运维中心 → 通知记录」排查。

## 11. 敏感数据加密方案

### 11.1 密钥管理

| 项 | 方案 |
|---|---|
| 算法 | AES-256-GCM（密文格式：`v1 || iv(12B) || ciphertext || tag(16B)`，首字节为密钥版本） |
| 密钥位置 | **环境变量 / 密钥管理服务**，不落库、不进代码仓；`sys_config` 只存 key 名称 |
| 密钥轮换 | 首字节版本号支持多版本共存；轮换任务按版本重加密，灰度可回滚 |
| HMAC 密钥 | 与 AES 密钥**分离**（不同 key），避免一处泄露双重失守 |
| 传输 | 全站 HTTPS；设备回调走内网 + 预共享密钥签名 |

### 11.2 字段对照

| 表.字段 | 加密 | HMAC 索引 | 脱敏展示 |
|---|---|---|---|
| `employee.id_card_*` | ✅ | ✅ 唯一 | ✅ 前 6 后 4 |
| `employee.phone_*` | ✅ | ✅ 唯一 | ✅ 前 3 后 4 |
| `visitor.id_card_*` | ✅ | ✅ 唯一 | ✅ |
| `visitor.phone_*` | ✅ | — | ✅ |
| `appointment.visit_phone_*` | ✅ | — | ✅ |
| `appointment_mate.id_card_*` | ✅ | — | ✅ |
| `blacklist.target_*` | ✅ | ✅ 唯一 | ✅ |
| `device.api_password` | ✅（可逆，需调设备） | — | 界面只显示 `******` |
| `sys_user.password_hash` | BCrypt（不可逆） | — | — |

### 11.3 查询规范（写进代码规约）

```java
// ✅ 正确：按 HMAC 查
employeeMapper.selectByIdCardHmac(Crypto.hmac(idCard));
// ❌ 禁止：按明文 LIKE 或全表扫描后解密
```

- 任何接口返回身份证号/手机号时，**只返回 `_mask` 字段**；
- 只有「预约详情、通行记录详情、管理员导出」三类高权限操作才解密，且必须落 `audit_log`；
- Excel 导出身份证号默认脱敏，需要明文时需二次授权并记录原因。

### 11.4 合规映射

| 规则 | 落地 |
|---|---|
| BR-D-006 抓拍/证件照 30 天 | `access_event_media.expire_at` + JOB-06 |
| BR-D-007 通行/审批 12 个月 | JOB-008 归档 |
| BR-D-008 证件号加密 + 展示脱敏 | §11.1~11.3 |
| BR-D-010 审计 3 年不可删 | `audit_log` 只 INSERT，DB 账号无 DELETE 权限 |

**容量与保留**（估算 100 人 + 日均 200 次通行）：

| 表 | 增长 | 策略 |
|---|---|---|
| `access_event` | ~7 万/年 | 12 个月后归档到 `access_event_arc_yyyy` |

> `device_heartbeat` 是全库增长最快的表，必须在 P1 就实现滚动清理，否则一年后单表百万行。若只需"在线状态"，可不落库、仅更新 `device`（保留 `raw` 3 天用于排障）。

## 13. 对象存储规范（MinIO / 云 OSS）

### 13.1 Key 规则

```
{bucket}/
  emp-face/{employeeId}/{yyyyMMdd}/{sha256前16}.jpg        员工原始照片
  emp-face-std/{employeeId}/{yyyyMMdd}/{sha256前16}.jpg    压缩后下发件
  event/{yyyy}/{MM}/{dd}/{deviceId}/{eventUuid}-capture.jpg 抓拍
  event/{yyyy}/{MM}/{dd}/{deviceId}/{eventUuid}-idcard.jpg  证件照
```

规则：**按日期分目录**（便于生命周期规则按前缀批量删除）、**文件名用 UUID/摘要**（不出现人名或身份证号）。

### 13.2 访问策略

| 项 | 设置 |
|---|---|
| Bucket ACL | **私有**（private） |
| 加密 | 服务端加密 SSE-KMS（或 SSE-OSS 托管密钥） |
| 访问方式 | 只发**预签名 URL**，有效期 **5 分钟** |
| 缩略图 | 列表页用 OSS 图片处理生成 200px 缩略，避免拉原图 |
| 水印 | 抓拍照片展示时叠加平台水印（时间 + 设备 + 人员脱敏号） |
| 生命周期 | `event/` 前缀配置 **35 天**自动删除（比 30 天多 5 天缓冲，防止与 JOB 抢跑） |
| 跨域 | 后台域名加入 OSS CORS，仅 `GET` |

### 13.3 上传流程

```
小程序/H5  →  POST /api/admin/upload/policy  →  返回预签名 PUT URL + key
          →  直传 OSS（不经应用服务器，节省带宽）
          →  POST /api/admin/employee/{id}/face { ossKey }
          →  应用 HEAD 校验 size/尺寸 → 写 employee_face → 触发压缩任务
```

> 直传的好处：100 人的照片批量导入不会打爆应用服务器内存；坏处是要在回调时做二次校验（尺寸、单脸检测）。
