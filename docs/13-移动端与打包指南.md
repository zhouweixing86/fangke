# 移动端与打包指南（uni-app 两端 + Web 管理端）

> 版本 v1.1 ｜ 2026-11-21
> 本目录：`uniapp/`。一套代码产出 **微信小程序（访客端）** 与 **H5（管理端）**。
> 原来的 `h5/`（Vant 版）已迁移并删除，避免两份代码并存。

---

## 1. 端矩阵（2026-11-24 更新，C-70 / C-76）

> **端的划分是硬要求**：
> 1. **访客端只有微信小程序**，没有 H5；
> 2. **员工/审批员不在小程序登录账号密码**：微信扫管理端「角色二维码」→ 填姓名+手机号 → 获得角色身份（C-76），
>    有角色的人在小程序多出「我的审批」，按审批模板里配置的角色处理待办；
> 3. **管理端有 H5 与 Web 两套**（H5 不再新增功能，只做存量维护）。

| 端 | 构建命令 | 产物 | 页面数 | 谁用 | 状态 |
|---|---|---|---|---|---|
| **Web 管理端**（另一套） | `cd web && npm run build` | `web/dist` | 16 页 | 管理员（PC 浏览器） | ✅ 已完成 |
| **管理端 H5**（uni-app） | `cd uniapp && npm run build:h5` | `uniapp/dist/build/h5` | **7 页**（登录 + 工作台/预约审核/通行记录/设备/黑名单/报表） | 保安、管理员（手机浏览器） | 🟡 存量维护（客户确认不再投入） |
| **访客小程序**（uni-app） | `npm run build:mp-weixin` | `uniapp/dist/build/mp-weixin` | **6 页**（首页/预约/我的预约/预约详情/绑定身份/我的审批+详情） | 访客、审批员、领导 | ⏳ 需要客户提供 AppID + 主体 + 备案 |

**访客小程序 6 个页面**：

| 页面 | 说明 |
|---|---|
| `pages/visitor/home` | 首页：LOGO + 「预约申请」「我的预约」；扫过角色码的人**额外显示「我的审批」**（带待办数角标）；进页即静默 `wx.login → /api/app/auth/wx-login` |
| `pages/visitor/new` | 预约表单：个人/团体切换、来访类型、来访日期 + **全天/上午/下午**、被访人手机→自动匹配被访人、姓名/手机号/**身份证**/公司/职务/车牌号、**来访区域（C-75）**、具体事由（50 字）；**团体预约填「同行人总数」自动展开同行人**；门点多于一个才出现选门控件 |
| `pages/visitor/index` | 我的预约：空态「无预约」；有单时卡片列表 + 状态标签 |
| `pages/visitor/appointment` | 预约详情：通行码、撤回、取消 |
| `pages/bind/bind` | **扫码绑定身份（C-76）**：管理端「角色二维码」扫码进入 → 显示即将获得的角色 → 填姓名 + 手机号 → 绑定并直接换新 token（可多次扫码叠加角色） |
| `pages/employee/approvals`、`approval` | **我的审批（C-76）**：待审批/已审批两个页签 + 审批详情（门点、二维码开关、意见、通过/驳回） |

> 管理端 H5 只允许「管理端账号」与「员工手机号」登录；访客手机号登录会被提示
> 「访客请使用微信小程序」，避免登录后无处可去（访客页面不在 H5 产物里）。
> 小程序侧 **没有登录页**：`App.vue` 在 `MP-WEIXIN` 下不做登录跳转，由首页/列表自行
> 调用 `wx-login`，未绑定（首次使用）也能先提交预约，提交后后端把 openid 绑到访客档案。

## 3. 本地开发

```powershell
cd D:\fangke\uniapp
npm install

# H5（端口 5175，/api 已代理到 127.0.0.1:8080）
npm run dev:h5

# 微信小程序（产物用微信开发者工具导入）
npm run dev:mp-weixin

# APP（产物用 HBuilderX 导入运行）
npm run dev:app
```

后端地址规则：

| 场景 | 配置 |
|---|---|
| H5 开发/同域部署 | 留空，前端请求 `/api`，由 vite 代理或 Nginx 反代 |
| H5 跨域部署 | 构建时 `VITE_API_BASE=https://your-domain` |
| 小程序 / APP | **必须**设绝对地址，如 `VITE_API_BASE=http://192.168.10.50:8080`（小程序还需在后台配 request 合法域名） |

### 3.1 局域网演示：让同事在另一台电脑上看

**Web 管理端（推荐，无需 CORS）**

```powershell
cd D:\fangke\web
npm run dev          # vite 已配 host: true，监听 0.0.0.0:5173
```

同事访问 `http://<本机IP>:5173`（如 `http://192.168.1.131:5173`）。
前端 `/api` 由 vite 代理到 `127.0.0.1:8080`，**浏览器不跨域，不用改 CORS**。

**H5 管理端（跨域，需重新构建 + 放行来源）**

H5 静态包没有代理，必须把后端绝对地址编进产物：

```powershell
cd D:\fangke\uniapp
$env:VITE_API_BASE = 'http://192.168.1.131:8080'   # 换成当前本机 IP
npm run build:h5
python -m http.server 5175 --directory dist\build\h5
```

同事访问 `http://<本机IP>:5175`。后端要放行该来源（已配在 `application-dev.yml`）：

```yaml
fangke:
  cors-allowed-origin-patterns:
    - http://192.168.*:*
    - http://10.*:*
    - http://172.16.*:*
```

> 预检请求（OPTIONS）不带 token，`AuthInterceptor` / `AppAuthInterceptor` 已显式放行，
> 否则浏览器跨域请求会全部 500（2026-11-24 修复）。

**三条注意事项**

1. **本机 IP 会变**：DHCP 换地址后，H5 要重新构建、`pull-public-base-url` 也要改；建议设静态 IP 或 DHCP 保留
2. **Windows 防火墙**：首次监听会弹窗，选「允许访问」；已放行 `node.exe` / `java.exe` / `python.exe` 时无需再操作
3. 后端本身监听 0.0.0.0:8080，不需要额外配置

## 4. 微信小程序上线步骤

1. 客户提供小程序 **AppID 与主体**，填入 `src/manifest.json → mp-weixin.appid`，
   并同时配置后端环境变量 `WX_APP_ID / WX_SECRET`（关掉 `WX_MOCK`）。
2. 在微信公众平台配置：
   - **request 合法域名**：后端 HTTPS 域名（小程序强制 HTTPS）
   - **业务域名**（若用 web-view）
3. 构建：`npm run build:mp-weixin`。
4. 微信开发者工具 → 导入 `uniapp/dist/build/mp-weixin` → 上传体验版 → 提审发布。
5. 登录方式：小程序走 `wx.login → /api/app/auth/wx-login` 静默登录（openid 绑定访客档案）。
   员工/审批人通过管理端「角色二维码」扫码绑定身份（C-76）。

### 4.1 分享（C-81）

小程序页面通过 `onShareAppMessage` 开启右上角「转发」：
首页（另支持分享到朋友圈）、访客预约页、我的预约页。
「绑定身份」页**故意不开启分享**（避免把绑定入口转发给不该有该角色的人）。

### 4.2 角色二维码：链接码 vs 小程序码（C-81）

| | 链接二维码（当前默认） | 小程序码（推荐，配置 AppID 后自动切换） |
|---|---|---|
| 内容 | `http://<域名>/bind?t=<token>` | 微信 `wxacode.getUnlimited` 生成的图片 |
| 微信扫一扫 | **只会用浏览器打开网页**，进不了小程序 | **直接唤起小程序**并进入「绑定身份」页 |
| 前提 | 无 | 已配置 `WX_APP_ID/WX_SECRET`、小程序已发布对应 `WX_ENV_VERSION` 版本 |
| 落地 | nginx `location = /bind` → `bind.html`（显示角色 + 提示在小程序中打开） | 小程序 `pages/bind/bind`（scene=`t=<token>`） |

> 生产目前未提供 AppID，所以管理端显示的是链接二维码 + 黄色提示；
> 填好 `WX_APP_ID/WX_SECRET` 并重启后端后，角色二维码页会自动改为小程序码。

### 4.3 没有正式小程序时怎么做真机测试（C-81 补充）

微信**没有**像公众号那样的「小程序测试号」；开发者工具里的「测试号」只是本地虚拟 AppID，
**不能上传、不能生成二维码给手机扫**，所以只能用来跑模拟器。

真机测试的现实路径：**注册一个免费的个人主体小程序，用「开发版」测**。

| 阶段 | 需要什么 | 是否需要备案 / 审核 / HTTPS |
|---|---|---|
| 开发者工具模拟器 | 测试号 | 否 |
| **开发版**（真机，仅开发者可扫） | 注册小程序（个人主体免费）+ 添加开发者 | **否**；手机端「···→ 打开调试」可关闭域名校验，能直接连 `http://IP` |
| 体验版（真机，体验成员可扫） | 同上 + 添加体验成员 | 需要配置 request **合法域名**（HTTPS + 已备案域名） |
| 正式版 | 企业主体 + 类目资质 + 发布 | 需要备案、审核、HTTPS |

个人主体注意点：
- 注册免费，一个微信号可注册多个；开发/体验阶段**不走类目审核**，所以「访客预约」这类企业内部用途也能先测；
- 个人主体后续基本无法通过「企业内部管理」类目上架，正式上线仍需企业主体；
- 开发版只有**项目成员（开发者）**能扫码打开，最多加若干人；给审批员测就把他们加成开发者/体验成员。

要让「角色二维码」变成小程序码，把 AppID/AppSecret 填进服务器后：
- 正式版：`WX_ENV_VERSION=release`
- 体验版：`WX_ENV_VERSION=trial`
- 开发版：`WX_ENV_VERSION=develop`（只有开发者能扫开）

> 用开发版测时，手机端必须先在对应小程序里「打开调试」，否则 `http://58.87.99.249` 会被域名校验拦掉。

## 5. APK 打包步骤

1. 构建资源：`npm run build:app`（产物 `uniapp/dist/build/app`）。
2. 用 **HBuilderX** 导入该目录 → 发行 → 原生 App-云打包（或本地打包）。
3. 必填：
   - Android 包名，如 `com.fangke.visitor`
   - 签名证书（.keystore + 别名 + 密码；**证书要留存，后续升级必须同一张**）
   - 图标、启动图
4. `manifest.json` 已声明权限：`CAMERA`（扫通行码）、`INTERNET`、`ACCESS_NETWORK_STATE`。
5. 装到保安 PDA 后：登录管理端账号 → 工作台/预约/通行/设备四个页签；
   扫码核验在「工作台 → 待办」之外由后端 `/api/guard/qr/verify` 支持（页面后续可加扫码按钮）。

> 若不想用 HBuilderX 云打包，可用 Android Studio 走 uni-app 离线打包 SDK；
> 云打包更省事，但需要 DCloud 账号（免费额度够用）。

## 6. 登录与角色路由

| 身份 | 登录方式 | 落地首页 | 底部导航 |
|---|---|---|---|
| 访客 `APP_VISITOR` | 手机号 + 验证码 | 我的预约 | 预约 / 新预约 / 消息 / 我的 |
| 员工 `APP_EMPLOYEE` | 手机号 + 验证码 | 待我审批 | 待办 / 消息 / 我的 |
| 管理员 / 保安 `ADMIN`、`GUARD` | 账号 + 密码 | 工作台 | 工作台 / 预约 / 通行 / 设备 |

- token 与后台一致（JWT，8 小时），存 `uni.setStorageSync('fk_token')`。
- 管理端接口统一要求 `ADMIN`（拦截器集中校验），保安账号访问管理端会 403，只能走 `/api/guard/**`。
- 401 自动清 token 并回登录页。

## 7. 后端依赖（本次为三端补的）

| 改动 | 原因 |
|---|---|
| 新增 `QrImageService`（zxing 生成 PNG，Base64 返回） | 小程序/APP 没有 DOM，前端 canvas 二维码方案不可用；改成后端出图，三端只放 `<image>` |
| 二维码接口返回新增 `qrImage` 字段（签发/保安端/访客端三处） | 同上，失败时返回 null，前端自动退化为只显示文本码 |
| CORS 允许 `http://localhost:5175` | uni-app H5 默认端口 |
| 短信网关（未接） | 手机号验证码登录依赖短信；开发模式 `APP_SMS_MOCK=true` 会回显验证码，**生产必须接网关** |

## 8. 已知限制

| 项 | 说明 |
|---|---|
| 小程序 web-view | 未使用；页面是原生 uni-app 组件，体验更好 |
| 管理端小程序 | 暂不做；代码已就绪，填 AppID 即可尝试 |
