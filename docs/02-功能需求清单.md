## 2. 访客端

### P-V-01 访客首页

- **角色**：访客
- **入口**：小程序首页 / H5 首页
- **前置**：已微信授权

| 区域 | 内容 | 说明 |
|---|---|---|
| 顶部 | 状态卡片 | 有进行中预约时显示"您有 1 个进行中的预约"，点击进入 P-V-06 |
| 主按钮 | 「预约来访」 | 首次点击 → 若未同意告知，跳 P-V-02；已同意 → 跳 P-V-03 |
| 次入口 | 「我的预约」 | 跳 P-V-05 |
| 说明区 | 到访须知 | 需携带身份证、到访时段、门点位置 |

**异常**：未登录 → 触发微信授权；授权失败 → 提示"请允许授权后使用"。

**关联**：BR-P-020

### P-V-02 个人信息告知与同意

- **角色**：访客
- **入口**：首次预约前

| 字段/元素 | 控件 | 必填 | 规则与提示 |
|---|---|---|---|
| 告知正文 | 富文本 | — | 内容由客户审定（CMP-03） |
| 同意勾选 | 复选框 | 是 | 未勾选时「同意并继续」按钮置灰 |
| 同意时间 | 后台记录 | — | 记录时间戳与版本号 |

**操作**

| 按钮 | 行为 |
|---|---|
| 同意并继续 | 记录同意 → 跳 P-V-03 |
| 暂不同意 | 返回 P-V-01，不可预约 |

**关联**：BR-P-020、BR-D-003

### P-V-03 预约表单

- **角色**：访客
- **入口**：P-V-01 / P-V-02

**访客信息**

| 字段 | 控件 | 必填 | 校验与提示 |
|---|---|---|---|
| 所属单位 | 只读文本 | — | **固定展示本园区单位名称**，不可编辑、不入库为访客属性 |
| 姓名 | 输入框 | 是 | 2~20 字；空 → "请填写姓名"；超长 → "姓名最多 20 字" |
| 手机号 | 输入框（数字） | 是 | 11 位且以 1 开头；不合法 → "请输入正确的手机号" |
| 身份证号 | 输入框（大写） | 是 | 18 位 + 校验位；不合法 → "身份证号有误，请核对" |
| 访客类型 | 下拉选择 | 是 | 选项：商务 / 施工 / 送货；未选 → "请选择访客类型" |
| 车牌号 | 输入框（大写） | 否 | 7~8 位；仅登记，不做车辆放行；格式不符 → "车牌号格式有误" |

**被访信息**

| 字段 | 控件 | 必填 | 校验与提示 |
|---|---|---|---|
| 被访人手机号 | 输入框（数字） | 是 | 11 位；不合法 → "请填写被访人手机号"；说明文案："请向接待您的同事索取手机号" |

**来访信息**

| 字段 | 控件 | 必填 | 校验与提示 |
|---|---|---|---|
| 来访日期 | 日期选择 | 是 | 今天起 30 天内；早于今天 → "请选择今天或之后的日期" |
| 开始时间 | 时间选择 | 是 | 与日期组合后不早于 now+10min；否则 "请选择未来时段" |
| 结束时间 | 时间选择 | 是 | 必须晚于开始；跨度 ≤24h；否则对应提示 |
| 来访事由 | 多行输入 | **否** | ≤100 字；超长提示 |

**同行人（可折叠）**

| 字段 | 控件 | 必填 | 校验与提示 |
|---|---|---|---|
| 同行人姓名 | 输入框 | 是（添加行后） | 2~20 字；空 → "请填写同行人姓名" |
| 同行人手机号 | 输入框 | 否 | 填写则校验 11 位 |
| 同行人身份证号 | 输入框 | **按后台配置** | 开关开启时必填并校验 18 位；与主访客重复 → "该证件号已填写" |
| 「添加同行人」 | 按钮 | — | 最多 5 行，超出 → 按钮置灰 + "最多添加 5 位同行人" |
| 「删除」 | 图标按钮 | — | 立即移除该行 |

**同行人身份证开关的两种表现**

| 开关状态 | 表单表现 | 通行方式 |
|---|---|---|
| 关闭（默认） | 不显示身份证列，只填姓名 + 手机号 | 随主访客一次通行放行，各生成一条随行记录 |
| 开启 | 显示身份证列且必填 | 同行人各自下发白名单，**必须各自刷身份证**通过；主访客不能带人 |

**操作与结果**

| 按钮 | 行为 |
|---|---|
| 提交 | 全部校验通过 → 生成预约单 → 跳 P-V-04；不通过 → 首个错误字段高亮并滚动定位 |
| 取消 | 返回上一页，不保留草稿 |

**提交时的服务端校验**（按顺序）

1. 黑名单命中 → 提示"暂无法受理，请联系接待人"（BR-P-018）
2. 同一证件同时段已有有效预约 → 提示"该时段已有预约（单号 X）"（BR-P-005）
3. 爽约次数超限 → 提示"近期爽约较多，暂无法预约"（BR-P-019，默认关闭）
4. 匹配被访人手机号 → 命中则指派该员工，未命中指派默认审批人（BR-A-002/003）

**关联**：BR-P-001~025、BR-A-002、BR-A-003

### P-V-06 预约详情与通行码

| 区域 | 内容 |
|---|---|
| 状态区 | 状态标签 + 一行说明（如"等待张经理审批，已等待 1 小时"） |
| 通行码 | **动态二维码（60 秒有效、可重复通过）+ 倒计时 + 「刷新」按钮**；仅在"可通行/已签到"状态显示 |
| 基本信息 | 姓名、脱敏证件号、手机号、单位 |
| 来访信息 | 时段、事由、被访人（脱敏） |
| 同行人 | 姓名 + 脱敏证件号列表；**提示"同行人与您一同通过即可，无需单独出示"** |
| 审批进度 | 一级/二级节点与处理结果（不含审批人手机号） |
| 底部操作 | 「撤回申请」（仅待审批且未超时）、「再次预约」、「取消」 |

**通行码区块规格**

| 项 | 规则 |
|---|---|
| 展示条件 | 仅主访客、且状态为"可通行"或"已签到" |
| 码有效期 | **60 秒**，从生成时刻起算 |
| 倒计时 | 显示剩余秒数，≤10 秒时数字变红 |
| 自动刷新 | 页面处于保安且剩余 ≤5 秒时自动请求新码 |
| 手动刷新 | 提供「刷新」按钮，可随时生成新码 |
| 重复使用 | **60 秒内可多次通过**，适用于进出同一扇门（入口刷一次、出口刷一次） |
| 同行人 | 主访客扫码一次，全部同行人一并放行，各生成一条通行记录（来源＝随行） |
| 离场 | 在**出口设备**同样可出示二维码；离场时若已过期，页面会提示"已过期，请刷新后离场" |
| 过期提示 | 倒计时归零未刷新 → 二维码遮罩 + "二维码已过期，请点击刷新" |
| 无网络 | 显示"网络异常，请改用身份证通行" |
| 防截图 | 码面叠加动态水印（预约单号 + 时间），降低截图转发价值 |

**展示规则**

| 状态 | 二维码区块 | 撤回按钮 |
|---|---|---|
| 待一级/二级审批 | 隐藏 | 显示 |
| 已通过（授权中） | 隐藏，显示"正在开通通行权限" | 隐藏 |
| 可通行 | 显示（60 秒动态码） | 隐藏 |
| 已签到（在场） | 显示（用于离场） | 隐藏 |
| 已驳回 | 隐藏，显示驳回原因 | 隐藏 |
| 已过期 / 已签离 / 已撤销 / 已撤回 | 隐藏 | 隐藏 |

**校验失败提示文案**

| 失败原因 | 设备/页面提示 |
|---|---|
| 已过期 | "二维码已过期，请刷新" |
| 无授权或已撤销 | "暂无通行权限" |
| 门点不匹配 | "该码不适用于此门点" |
| 不在授权时段内 | "当前不在可通行时段" |
| 网络异常 | "网络异常，请改用身份证" |

**关联**：BR-P-014、BR-P-015、BR-P-016、BR-V-007、BR-V-018~029、BR-N-005

### P-V-07 现场自助登记

- **角色**：访客（已到门口，未预约）
- **入口**：扫描大门张贴的"现场登记码"（二维码内含 `source=onsite_self` 与门点标识）
- **前置**：已在门口；微信授权完成

**页面构成**

| 区域 | 内容 |
|---|---|
| 顶部标识 | 醒目提示"现场登记 · XX 公司"，与预约场景区分 |
| 表单 | **复用 P-V-03 全部字段**（姓名、手机、身份证、访客类型、车牌、被访人手机、时段、事由、同行人） |
| 时段默认值 | 自动带出"现在 ～ 现在 +2 小时"，可修改 |
| 提交按钮 | "提交并等待确认" |

**提交后表现**

| 状态 | 页面表现 |
|---|---|
| 待审批 | 显示进度："等待 张经理 确认，已等待 0 分 30 秒" + 「催办」按钮（每分钟 1 次） |
| 已通过 / 授权中 | "正在开通通行权限，请稍候" |
| 可通行 | 绿色提示"请刷身份证进入" + 二维码（未带证件时用） |
| 已驳回 | 红色提示 + 驳回原因 + "请联系接待人" |

**与普通预约的差异**

| 项 | 普通预约（P-V-03） | 现场自助登记（P-V-07） |
|---|---|---|
| 入口 | 首页点「预约来访」 | 扫门口二维码 |
| 时段 | 手动选择 | 默认当前时间起 2 小时 |
| 授权优先级 | 增量下发 | **实时下发（优先）** |
| 撤回 | 可撤回 | 不可撤回（人已在现场） |
| 首页 | 无特殊标识 | 顶部标识"现场登记" |

**异常**

| 情况 | 提示 |
|---|---|
| 已在门口且已有进行中预约 | "您已有进行中的预约（单号 X）"，直接跳 P-V-06 |
| 被访人手机号匹配不到 | 正常提交，由默认审批人处理 |
| 设备离线 | "门禁设备暂时不可用，请联系门卫" |

**与手机扫码的差异**

| 项 | 手机扫码 | 门卫室自助终端 |
|---|---|---|
| 载体 | 访客自己的手机 | 门卫室电脑（全屏 H5，Kiosk 模式） |
| 登录 | 微信授权 | 免登录访客模式，仅绑定本次登记 |
| 隐私 | 提交后访客可随时查看 | 提交后自动退出并清屏，防止下一位看到上一位信息 |
| 适用 | 有手机的正常访客 | 无手机、不会操作、手机没电 |

**关联**：BR-S-013、BR-S-014、BR-S-015、BR-P-001~025、BR-V-018~029

### P-E-03 审批详情

- **入口**：P-E-02 / P-E-07
- **角色**：一级或二级审批人

| 区域 | 内容 |
|---|---|
| 访客信息 | 姓名、脱敏证件号、手机号、单位、证件照（点击放大） |
| 来访信息 | 时段、事由、同行人清单 |
| 匹配说明 | 若走默认审批人：显示"访客原填手机号：138****1234"（BR-A-004） |
| 审批链 | 已完成的节点（人、时间、意见、耗时）、当前节点、后续节点 |
| 风险提示 | 黑名单命中、重复预约、爽约记录（若有） |
| 底部操作 | 通过 / 驳回 / 转办 / 加签 |

**「通过」交互**

| 配置 | 交互 |
|---|---|
| 一级审批 + 配置 2 级 + 候选池 >1 人 | 弹窗：选择二级审批人（下拉，必选）+ 审批意见（选填） |
| 一级审批 + 配置 2 级 + 候选池 = 1 人 | 弹窗：显示自动选中的二级审批人（不可改）+ 审批意见 |
| 一级审批 + 配置 1 级 | 确认弹窗 + 审批意见 |
| 二级审批 | 确认弹窗 + 审批意见 |

未选择二级审批人 → 提交按钮置灰 + 提示"请选择二级审批人"（BR-A-005）

**「驳回」交互**：必填原因（5~200 字）+ 二次确认"驳回后预约将终止，是否继续"（BR-A-009）

**「转办」交互**：选择接收员工 + 转办说明（BR-A-010）

**「加签」交互**：选择员工 + 加签原因；加签节点排在当前节点之后（BR-A-011）

**状态限制**：任务已被处理 → 页面只读，显示"该任务已由 XX 于 XX 时间处理"

**关联**：BR-A-005~011、BR-A-018

### P-E-04 邀请访客

| 字段 | 控件 | 必填 | 校验与提示 |

| 访客姓名 | 输入框 | 是 | 2~20 字 |
| 身份证号 | 输入框 | 是 | 18 位校验 |
| 手机号 | 输入框 | 否 | 11 位校验（填写则校验） |

### P-F-04 人工开门

> 保安**唯一的实质性操作**。两种场景：员工刷脸失败、访客已授权但凭证不可用。
> 前置硬约束：**只能对已有有效授权的人开门**（BR-S-016）。

**场景 A：员工刷脸失败**

| 字段 | 控件 | 必填 | 规则 |
|---|---|---|---|
| 员工工号 | 输入框 | 是 | 6 位；不存在 → "未找到该工号" |
| 员工姓名 | 只读 | — | 输入工号后自动带出，供核对 |
| 开门原因 | 下拉 + 备注 | 是 | 刷脸失败 / 未携带证件 / 其他 |
| 操作人 | 自动记录 | — | 当前登录保安账号 |

**操作**：「确认开门」→ 二次确认 → 执行 → 记录（员工、时间、操作人、原因）

**场景 B：访客已授权但凭证不可用**

入口方式：从「在访列表」中选中该访客点「远程开门」，或手工输入预约单号。

| 字段 | 控件 | 必填 | 规则 |
|---|---|---|---|
| 访客 | 从列表选择 / 输入预约单号 | 是 | **系统自动校验授权状态**：未授权或已过期 → 按钮置灰 + "该访客暂无有效授权" |
| 授权信息 | 只读 | — | 显示预约时段、被访人、审批结果 |
| 开门原因 | 下拉 | 是 | 手机没电 / 二维码扫不出 / 证件消磁 / 其他 |
| 操作人 | 自动记录 | — | 当前登录保安账号 |

**硬约束**

- 未获得授权（待审批 / 已驳回 / 已过期 / 已撤销）→ **不提供开门按钮**
- 每一次开门都记录：访客、时间、原因、操作人，并出现在异常清单中

**异常**：设备离线 → "设备离线，无法远程开门"

**关联**：BR-V-003、BR-V-030、BR-E-001、BR-S-016
