## 2. 部署目标怎么切（前端 / 小程序）

| 场景 | 命令 | 实际连的后端 |
|---|---|---|
| 小程序本地开发 | `npm run dev:mp-weixin` | `.env.development` → `http://58.87.99.249`（**生产**，只读调试） |
| 想让小程序连**测试**服务器 | 临时覆盖：`$env:VITE_API_BASE='http://47.103.158.76:8082'; npm run dev:mp-weixin` | 测试环境 |
| 小程序正式打包 | `npm run build:mp-weixin` | `.env.production` → `https://lswz.com.cn`（**生产**） |
| 管理端 Web 构建 | `cd web && npm run build` | 相对路径 `/api`，跟随访问域名 |

> 约定：**`.env.development` / `.env.production` 永远指向生产**；要连测试环境一律用临时环境变量覆盖，不改文件，避免误把测试地址打包进去。

## 4. 必须注意的坑

1. **阿里云 8082 未放行** → 外网访问不到。要么在安全组加 TCP 8082 规则，要么把测试站改到 80 的子路径（如 `/fangke/`）。
2. **这台机器内存只有 1.8 GB**（还跑着 openGauss、RustDesk 中继、另一个 Java 服务 `pinDouServer:8080`，靠 swap 撑着）→ 不要在上面跑压测生成大负载，也不要把 `-Xmx` 调大（当前 `-Xmx256m`）。
3. **同一台机器上有别人的项目**：改 nginx / 端口 / Docker 前先确认不冲突（8080 是 `pinDouServer`，888 是宝塔默认站，3306 是宿主机 MySQL）。
4. **两套环境的 `.env` 不能互拷**：数据库口令、`JWT_SECRET`、`CRYPTO_*` 均不同；互拷会导致 token/加密数据错乱。
5. **测试环境没有备份**：需要造数据压测时，先自己 `mysqldump` 一份，或直接用 `docker` 卷快照。
6. 阿里云安全组当前对 `5432`（openGauss）对全网开放、宿主机 MySQL 监听 `*:3306` —— 与本项目无关但属于风险项，建议找机会收紧。
