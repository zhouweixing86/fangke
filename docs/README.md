## 二、各文档要点

### 01 业务需求说明书

- **12 章**：引言 / 角色职责 / 业务对象与生命周期 / 业务规则 / 业务流程 / 页面清单 / 报表 / 异常兜底 / 权限矩阵 / 合规 / 验收 / 附录
- **130 条业务规则**，按 8 个业务域编号：`BR-P` 预约、`BR-A` 审批、`BR-I` 代邀、`BR-S` 现场、`BR-V` 通行、`BR-E` 员工、`BR-N` 通知、`BR-D` 数据合规
- **46 条验收标准**，场景化描述（前置 → 操作 → 预期）
- 不含任何技术实现内容，可直接交客户评审签字

### 02 功能需求清单

- **30 个页面**，分访客端（7）、员工端（7）、保安工作台（4）、管理端（12）
- 每页含：角色、入口、字段表（控件/必填/校验与提示）、操作、状态展示规则、异常提示、关联规则
- **9 个定时任务**
- 末尾附「需求 ↔ 规则」映射表，便于追溯

### 03 需求确认记录

- **59 条已确认结论**（C-01~C-59），含确认方式与影响
- **32 项待确认**（Q-01~Q-32），标注责任人与阻塞阶段
- **8 项现场验证前置**（V1~V8）
- **20 项风险登记**（R-01~R-20）
- 签字确认页

### 04 W0 现场验证清单

八项硬件事实，可在半天内验完，但结论会决定方案是否成立：

| 项 | 验证内容 | 最关键的原因 |
|---|---|---|
| V1 | 白名单按证件号还是人脸匹配 | 若按人脸，访客必须采照片，核心设计失效 |
| V3 | 有效期是否真正生效 | 若不生效，访客名单永不过期 |
| V2 | 固件是否支持在线比对 | 决定现场登记有无兜底 |

### 09 开发计划与技术架构

- 设备通道只有**轮询式终端（PULL）**：设备主动调平台 `/openapi/v1/**`；原「局域网推（8091）+ 设备回调」通道（九鼎）已随设备下线移除
- **设备适配层**：`OpenApiPullAdapter`（在用）/ `MockDeviceAdapter`（自测）/ `CloudMqttAdapter`（占位），统一语义方法
- 13 个模块 + 5 阶段开发顺序（先做设备中心，因为它外部依赖最多）
- 接口分组与鉴权、设备回调契约（含"必须回 ok"等协议硬约束）、统一错误码与通道错误映射
- 8 条关键技术决策（含理由与代价）、6 个里程碑估算（合计约 11.5 周）
- §8 只保留 **6 项技术待验证**；商务/网络/施工等非开发事项移到 §8.2，由项目经理推进

### 10 数据库设计

- **33 张表**，按 9 个域分组（组织 / 门点设备 / 访客 / 审批 / 授权下发 / 通行 / 凭证 / 系统 / 日志），含完整 `CREATE TABLE` DDL
- 敏感字段三段式：`_enc`（AES-256-GCM，带密钥版本）+ `_hmac`（HMAC-SHA256，**做唯一索引**）+ `_mask`（脱敏展示），禁止按明文查询
- 关键机制：`uk_event_uuid` 幂等（设备重推去重）、`device_cmd` 串行出队 SQL、`person_device_state` 对账、`credential` 只存码摘要
- **客户云 OSS 规范**：key 规则按日期分目录、私有桶 + KMS、预签名 5 分钟、35 天生命周期、前端直传 + 回调二次校验
- 容量评估与保留策略：点名 `device_heartbeat` 是全库最快增长表（年百万行），必须 P1 就做滚动清理
- 合规映射：30 天照片清理、12 个月记录归档、3 年审计日志（应用账号无 DELETE 权限）

### 11 接口详细契约

- **70+ 端点**：设备回调 5 / 访客端 8 / 员工端 13 / 保安端 6 / 管理端约 40，含请求响应示例
- **设备回调鉴权按真实报文写**：设备不发自定义头，只能靠「IP 白名单 + SN 校验 + `password` 字段」，并明确要求回调网段不对公网暴露
- 关键细节落地：心跳 `currentTime` 是 **Unix 秒字符串**、记录回调「先落库再返回 ok」、在线比对 P99<300ms 且不查远程
- 二维码判定给出 7 步顺序（验签→过期→状态→时段→门点）与对应 `status` 码
- 错误码全表 **40 条**（1xxx 参数 / 2xxx 鉴权 / 3xxx 业务 / 4xxx 设备 / 5xxx 系统）
- 两张时序图：预约→审批→下发→通行、二维码在线比对
- 授权签发内部规则明确「按自然日整段（00:00–23:59）」，与 C-60 一致
