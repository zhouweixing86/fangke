# 新设备接入指南（轮询式终端）

> 版本 v2.0 ｜ 2026-11-19
> **平台现在只有一种设备通道：`PULL`（HTTP 客户端版，设备主动来拉）。**
> 原「局域网推送」通道（九鼎 YC-P208）已随设备下线，代码与 06/07/08 文档一并删除。
> 协议细节（13 个端点、签名、字段映射）见 [14 设备协议 · 新终端 HTTP 轮询版](./14-设备协议-新终端HTTP轮询版.md)；
> 本文只讲**要做什么、按什么顺序做、怎么验收**。

---

## 1. 先理解一件事：平台不能主动连设备

| | 这套系统 | 传统门禁（已下线） |
|---|---|---|
| 谁发起 | **设备每 30 秒来问平台** | 平台去连设备 |
| 名单下发 | 平台入队 → 设备心跳取 `action` → 设备再来拉详情 | 平台直接推 |
| 延迟 | 最迟一个心跳周期（默认 30s） | 实时 |
| 远程开门 | 随心跳下发，最迟 30s | 实时 |
| 平台读设备 | ❌ 协议没有「平台问设备」的接口 | ✅ |

**推论**：现场能不能用，取决于**设备能不能访问到平台 IP:8080**，而不是平台能不能访问设备。

---

## 2. 平台保留 / 不保留哪些设备操作

| 平台能做 | 平台不能做（必须在设备屏幕操作） |
|---|---|
| 设备自动登记、档案维护、分配门点 | 读设备参数 |
| 远程开门（随心跳下发） | 写设备参数 |
| 能力矩阵查看 | 名单对账（拉取设备实际名单） |
| 名单/照片下发、删除 | 接入自检（读版本/参数） |
| 通行记录接收、照片回传 | 屏幕提示 |

> 已下线的接口：`/params/read`、`/params`、`/resync`、`/selfcheck`、`/message`。
> 前端设备页只保留「档案」和「开门」。

---

## 3. 设备到货：5 个参数必须在设备屏幕配好

| 设备菜单项 | 填什么 |
|---|---|
| `thirdHttpUrl` | `http://<平台IP>:8080/openapi/v1` |
| `thirdHttpkey` | 与平台 `DEVICE_PULL_SIGN_KEY` **完全一致** |
| `thirdOpenDoorLocal` | `0`（二维码交平台判定） |
| `thirdQrUrl` | `http://<平台IP>:8080/openapi/v1/qrCodePush` |
| 记录推送地址 | `http://<平台IP>:8080/openapi/v1/uploadDetectRecord` |
| 心跳间隔 | 30 秒（平台会在 `heartTime` 里再下发一次） |

**闸机相关（干接点）**：设备侧还要设 `recogRelay=1`（识别后继电器输出）、`delayvalue=1`（闭合 1 秒）、
`relayMode=0`（标准模式）。设 `recogRelay=0` 时识别通过继电器不动作，必须平台远程开门——断网就开不了闸。

**平台侧环境变量**：

```powershell
$env:DEVICE_PULL_SIGN_KEY      = '<与设备 thirdHttpkey 相同>'
$env:DEVICE_PULL_PUBLIC_BASE_URL = 'http://<设备能访问到的平台IP>:8080'
```

## 4. 接入步骤

### 第 0 步：没有设备也能先跑通（Mock 通道）

设备没到货时，用 `channel=MOCK` 的设备跑审批/下发/记录全链路，验证业务逻辑。

### 第 1 步：网络先通（这一步不过，后面都白搭）

| 检查 | 做法 |
|---|---|
| 同网段 | 设备与平台在同一网段，或路由可达 |
| 平台 IP 固定 | DHCP 保留或静态；设备里写死了平台地址，变了就全掉线 |
| **防火墙放行 8080 入向** | `New-NetFirewallRule -DisplayName "fangke-8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Any` |
| 关掉 AP 隔离 | 企业 WiFi 的「客户端隔离」会导致同 WiFi 设备互不可见 |
| 建议有线 | 用网线接交换机，比 WiFi 稳定 |

### 第 2 步：设备首次心跳 → 自动登记

设备配好参数启动后，平台会自动登记一台 `channel=PULL` 的设备**落在「待分配」门点**。

- 到「设备管理」能看到它（SN 已登记，mac 是 `PULL-<SN>` 占位）
- 填 mac / 型号 / 位置，并**分配到真实门点**（不分配，这个门的名单不会下发给它）

### 第 3 步：名单与照片

| 对象 | 触发方式 |
|---|---|
| 员工 | 保存员工 / 换照片 / Excel 导入 → 自动按全部启用门点建长期授权并下发（含照片） |
| 访客 | 被访人确认 + 门卫复核 → 按批准门点下发（有效期=预约当天） |
| 访客照片 | 访客在「我的 → 人脸通行」自助采集 → 带图重推 |

新增门点后，点一次「员工管理 → 同步名单」把历史员工补到新门点。

### 第 4 步：五条主链路验收

| # | 链路 | 判定 |
|---|---|---|
| 1 | 心跳 → 设备在线、IP/人数入库 | 设备页「在线」。峰值日志里签名校验通过 |
| 2 | 员工保存 → 设备名单 +1（含照片） | 设备刷脸能开 |
| 3 | 访客审批通过 → 设备名单 +1 | 刷身份证能开 |
| 4 | 刷证/刷脸 → 记录回传 | 后台「通行记录」有记录、证件号脱敏 |
| 5 | 撤销/停用 → 设备名单 -1 | 再刷不开 |

完整的 10 条必验清单见 [14 §10.3](./14-设备协议-新终端HTTP轮询版.md)。

### 第 5 步：换机与回滚

- 新设备直接配参数上线，自动登记后分配到对应门点即可
- 旧设备停用（`status=0`）后不再参与下发与对账
- 停用前建议先「同步名单」，把在岗员工补到新设备

## 5. 踩过的坑（新设备逐条复验）

| 坑 | 现象 | 处理 |
|---|---|---|
| 签名 key 不一致 | 所有请求返回 `{"code":1,"msg":"签名错误"}` | 平台 `DEVICE_PULL_SIGN_KEY` 与设备 `thirdHttpkey` 必须一字不差 |
| 设备时间偏差大 | 签名里的 `timestamp` 校验异常 | 设备 NTP 指内网时间源，偏差 > 5 分钟会失败 |
| 忘记分配门点 | 设备在线但从不收名单 | 设备停在「待分配」门点，去档案里分配 |
| 员工没传照片 | 员工能刷证、刷不开脸 | 设备按 `passAlgo=true` 跳过人脸；补照片会自动重推 |
| 设备离线时撤销 | 撤销后离线设备仍能刷开 | 本地校验的固有代价：删除指令要等设备上线；到期日（访客）会自然失效 |
| 防火墙未放行 | 设备心跳超时 | 放行 8080 入向，并确认不是 AP 隔离 |
| 远程开门"没反应" | 点了开门没动静 | PULL 通道要等下一次心跳（≤30s）；不是失败 |

---

## 6. 平台侧不用改的清单（给项目经理）

- 新增一台设备：**不用改代码**，配参数 → 自动登记 → 分配门点
- 新增一个门点：门点管理里新增 → 设备挂过去 → 点一次「同步名单」
- 换闸机/磁吸锁：只要设备继电器能驱动，**软件不用改**
- 换设备品牌：如果协议仍是这套 HTTP 客户端版，**不用改**；协议不同才需要写适配器
