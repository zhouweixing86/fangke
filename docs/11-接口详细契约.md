## 0. 通用约定

### 0.1 基础

| 项 | 约定 |
|---|---|
| Base URL | `https://{host}/api` |
| 编码 | UTF-8，`Content-Type: application/json; charset=utf-8` |
| 时间格式 | 请求/响应统一 `yyyy-MM-dd HH:mm:ss`；仅日期用 `yyyy-MM-dd` |
| 时区 | 服务端固定 `Asia/Shanghai`，不接受客户端时区 |
| 字段命名 | 小驼峰（与前端一致），**不出现下划线** |
| 空值 | 缺省字段不返回（`null` 仅在语义明确时返回） |
| 分页 | `page`（从 1 开始）、`size`（默认 20，最大 100） |

### 0.2 统一响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "0af7651916cd43dd8448eb211c80319c"
}
```

分页响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": { "total": 128, "page": 1, "size": 20, "list": [] },
  "traceId": "..."
}
```

> **设备接口例外**：设备只认自己的格式，`/openapi/v1/**` 的返回体是厂商格式 `{code,msg,data}`（见 §1），**不能套统一响应**。

### 0.3 鉴权

| 分组 | 方式 | 说明 |
|---|---|---|
| `/api/app/**` | `Authorization: Bearer {wxToken}` | 微信登录态换取的业务 token，有效期 2 小时，可刷新 |
| `/api/admin/**`、`/api/guard/**` | `Authorization: Bearer {jwt}` | JWT，含 `uid`、`roles`；PC 登录后签发，8 小时 |
| `/openapi/v1/**` | **顶层字段 MD5 签名**（`sign`） | 见 §0.4 |

### 0.4 设备接口的鉴权（重要，实现按此写）

设备只有一条通道 `PULL`：**设备调平台** `/openapi/v1/**`。原九鼎的 `/api/device/callback/**`
（设备 SN + 来源 IP + `password` 那套）已随设备下线移除。

| 层 | 做法 | 强度 |
|---|---|---|
| 1 | **顶层字段 MD5 签名**：除 `data` / `sign` 外字段按 ASCII 升序拼 `k=v&…`，末尾接 `&key=<thirdHttpkey>`，MD5 转大写 | 强 |
| 2 | 设备号校验：首次出现的设备自动登记（落在「待分配」门点），已登记的按 `device_sn` 匹配 | — |
| 3 | 通行记录推送**不校验签名**：文档示例本身不带 `sign`，丢记录代价高于假记录 | 弱，可接受 |

> **部署要求**：`/openapi/v1/**` 只对设备所在网段可达（防火墙/安全组限制）；
> 密钥通过环境变量 `DEVICE_PULL_SIGN_KEY` 注入，必须与设备 `thirdHttpkey` 一致。
### 0.5 幂等与时间窗

| 场景 | 幂等键 | 时间窗 |
|---|---|---|
| 记录回调 | `id`（设备生成 UUID）→ `access_event.event_uuid` 唯一 | 允许补推历史记录，**不校验时间窗** |
| 业务写接口 | 客户端传 `Idempotency-Key`（可选，10 分钟内重复请求返回首次结果） | 10 分钟 |
| 二维码校验 | `code_hash` + 60 秒有效期 | ±60 秒 |

### 0.6 限流

| 分组 | 限制 | 说明 |
|---|---|---|
| `/api/app/appointment` | 单访客 5 次/小时 | 防刷 |
| `/api/app/appointment/{no}/qrcode` | 单预约单 30 次/小时 | 60 秒刷一次，上限足够 |
| 其他 | 单账号 60 次/分钟 | 默认 |

## 1. 设备接口（设备 → 平台，通道 `PULL`）

> **原「局域网推送」通道（九鼎 YC-P208）已下线**，相关回调接口（心跳、通行记录、在线比对、
> 二维码独立回传、指令回执）已随代码一起移除，不再提供 `/api/device/callback/**`。
>
> 现在只有**轮询式终端**一种设备通道：设备主动调平台 `/openapi/v1/**`。
> 13 个端点、签名规则、名单同步流程、参数下发与真机验收清单见
> [14 设备协议 · 新终端 HTTP 轮询版](./14-设备协议-新终端HTTP轮询版.md)。

### 1.1 新终端（HTTP 客户端版，通道 `PULL`）

> 这类设备是 **HTTP 客户端**，全部请求由设备发起；平台只能靠心跳响应里的 `action` 指挥。
> 完整协议、签名规则、字段映射、真机验收清单见 [14 设备协议 · 新终端 HTTP 轮询版](./14-设备协议-新终端HTTP轮询版.md)。

| 方法 | 路径 | 作用 | 是否校验签名 |
|---|---|---|---|
| POST | `/openapi/v1/heartBeat` | 心跳，响应带 `action`/`heartTime` | ✅ |
| POST | `/openapi/v1/getAllDeviceWhiteList` | 拉平台全量名单索引 | ✅ |
| POST | `/openapi/v1/addDevicWhiteInfo` | 取"要新增的人" | ✅ |
| POST | `/openapi/v1/updateDeviceWhiteInfo` | 取"要更新的人" | ✅ |
| POST | `/openapi/v1/delDevicWhiteList` | 取"要删除的人" | ✅ |
| POST | `/openapi/v1/getDevicWhiteInfo` | 单人详情（含照片 base64） | ✅ |
| POST | `/openapi/v1/syncWhiteResult` | 增删改结果回执 | ✅ |
| POST | `/openapi/v1/getDeviceWhiteListCount` | 名单总数 | ✅ |
| POST | `/openapi/v1/syncDeviceTime` | 取时间 | ✅ |
| POST | `/openapi/v1/syncDeviceParameter` | 取参数 | ✅ |
| POST | `/openapi/v1/uploadDetectRecord` | 通行记录推送 | ❌（文档示例无 sign，丢记录代价更高） |
| POST | `/openapi/v1/qrCodePush` | 二维码推送，返回 `openGate` | ❌（设备固定格式） |
| POST | `/openapi/v1/checkPwd` | 密码开门（默认关闭） | ❌ |

响应体为厂商格式 `{"code":0,"msg":"成功","data":...}`，**不套平台 `ApiResponse`**。

### 1.2 车辆事件（车牌识别接入，C-68）

`POST /openapi/v1/vehicleEvent`

相机/车闸一体机推送车牌事件，平台判定后回 `openGate`。
**带 `sign` 就校验签名；不带也接受**（相机不支持签名时靠内网 + 门点约束）。

```json
{
  "ver": "v1.0",
  "deviceno": "CAR-GATE-EAST",
  "timestamp": "1795087200",
  "action": "vehicleEvent",
  "sign": "可选",
  "data": {
    "plateNo": "京A88888",
    "gateId": 8,
    "direction": 1,
    "time": "2026-11-19 16:40:00",
    "confidence": 93,
    "picData": "可选 base64 抓拍图"
  }
}
```

```json
{ "code": 0, "msg": "成功",
  "data": { "openGate": 1, "reason": "员工车辆", "plateNo": "京A88888",
            "matchedType": 1, "matchedName": "张三", "eventTime": "2026-11-19 16:40:00", "duplicate": false } }
```

| 字段兼容 | 别名 |
|---|---|
| 车牌 | `plateNo` / `plate` / `license` / `plateNum` / `carNo` |
| 时间 | `time` / `eventTime` / `timestamp`（秒/毫秒）/ `createTime` |
| 方向 | `direction` / `inout` |
| 设备号 | `deviceno` / `deviceNo` / `sn` |
| 抓拍 | `picData` / `image` / `photoBase64` |
| 事件号 | `eventId` / `id` / `tableID`（用于幂等） |

- `gateId` 不传时用 `deviceno` 反查设备档案的门点；两者都拿不到 → **拒绝**。
- 重复推送同一事件号只入库一条（幂等），返回 `duplicate: true`。
- 若相机只推不接指令（方案 A/C），忽略 `openGate` 即可，平台照常落记录。

## 2. 访客端接口（小程序 / H5）

### 2.0 登录与鉴权（App token）

| 方法 | 路径 | 是否需登录 | 说明 |
|---|---|---|---|
| POST | `/api/app/auth/code` | 否 | 发送验证码 `{"phone":"13800001234"}`；开发模式回显 `mockCode` |
| POST | `/api/app/auth/login` | 否 | `{"phone":"...","code":"123456"}` → `{token, role, subjectId, name, phoneMask}` |
| POST | `/api/app/auth/wx-login` | 否 | 微信小程序一键登录：`{"code":"wx.login 的 code"}` → `{token, role, subjectId, name, openid, bound}`；`bound=false` 表示该微信还未绑定访客档案（首次预约成功后自动绑定，`subjectId=0`）。开发期 `fangke.wx.mock=true` 时把 code 直接当 openid |
| GET | `/api/app/employee/lookup?phone=` | 否 | 被访人手机号 → `{matched, name, title, deptName}` 或 `{matched:false, message}`；只回姓名/职务/部门，不回手机号与证件号 |
| GET | `/api/app/me` | 是 | 当前身份（员工带 deptName/title，访客带 company/faceStatus） |
| POST | `/api/app/me/face` | 是（访客） | **访客自助采集人脸**（multipart `file`）：校验+压缩→存 MinIO→重推名单；返回 `{visitorId,faceStatus,devices,success,fail}` |

- `role`：`APP_EMPLOYEE`（员工手机号命中 `employee.phone_hmac` 且在岗）/ `APP_VISITOR`（命中 `visitor.phone_hmac`）。
- 都未命中 → `1002`「该手机号还没有登记记录，请先提交一次预约」。
- 验证码：6 位、5 分钟有效、最多试错 5 次、同号 60 秒内不可重发。
- **短信网关未接入**：`fangke.app.sms-mock=false` 时接口直接返回 `5004`，避免“以为发了”。
- 携带方式：`Authorization: Bearer <appToken>`；token 有效期 8 小时（同管理端 JWT 机制）。

> 无需登录的接口只有：`/api/app/auth/**`、`/api/app/privacy/**`、`/api/app/onsite/**`、
> `GET /api/app/gate`（选门点，不含敏感信息）、`GET /api/app/dict/**`（事由/区域字典，不含敏感信息）、
> 以及首次提交预约 `POST /api/app/appointment`（请求已含身份证 + 手机号 + 隐私同意）。
> 其余接口（我的预约、详情、撤回、取码、员工审批）都必须登录，并做**归属校验**。

### 2.0.3 微信角色绑定与「我的审批」（C-76）

管理端「角色二维码」页面为**每个后台角色**生成一个二维码，内容是小程序落地链接
`${VITE_MP_BIND_URL|当前域名}/bind?t=<token>`（正式环境需在微信后台配置「扫普通链接二维码打开小程序」，
或拿到 AppID 后改调 `wxacode` 接口生成小程序码）。

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/admin/wx-role-qr` | `user:read` | 角色二维码列表（首次访问自动生成 token），返回 `roleId/roleCode/roleName/token/bindCount` |
| POST | `/api/admin/wx-role-qr/{roleId}/regenerate` | `user:read` | 重新生成，旧码立即失效（已绑定的人不受影响） |
| GET | `/api/app/bind/preview?token=` | 公开 | 扫码页预览：这个码对应哪个角色 |
| POST | `/api/app/bind` | 公开 | `{token, wxCode, name, phone}` → 写入绑定并**直接返回新 token** |

绑定成功后 app token 里除 `APP_VISITOR/APP_EMPLOYEE` 外会多出 `APP_APPROVER` 与已授予的**角色编码**
（JWT 增加 `bindId` claim）；手机号命中员工档案时自动关联 `employee_id`。

小程序「我的审批」：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/app/approval/count` | 我的待办数（按绑定角色匹配 `approval_task.assignee_role`，只含角色任务） |
| GET | `/api/app/approval/todo?page=&size=` | 待审批列表 |
| GET | `/api/app/approval/done?page=&size=` | 已审批（我处理过的通过/驳回） |
| GET | `/api/app/approval/{taskId}` | 详情（含访客、门点、审批轨迹，`canAct` 判断能否处理） |
| POST | `/api/app/approval/{taskId}/pass` | `{comment, approvedGateIds?, qrApproved?}`；本节点办结后自动流转到下一节点或终审下发 |
| POST | `/api/app/approval/{taskId}/reject` | `{comment}` 必填，整单驳回 |

> 会签（`approve_mode=ALL`）节点的任务仍派给**具体后台账号**，小程序只处理角色任务；
> 审批轨迹记录 `operator_type=4 + operator_name`（微信审批人姓名）。

| 字段 | 必填 | 校验 |
|---|---|---|

| `company` | 否 | ≤128 字；为空时取 `visitor.company` |
| `position` | 否 | ≤64 字；为空时取 `visitor.position` |
| `period` | 否 | **1 全天 / 2 上午 / 3 下午**；传了它就不用传 `startTime`/`endTime`（后端换算：全 00:00-23:59、上午 00:00-12:00、下午 12:00-23:59）。不传则沿用 `startTime`/`endTime` |
| `groupCount` | 否 | 团体预约总人数（含负责人）；转换为 `mate_count = max(同行人数, 总人数-1)` |
| `mates[]` | 否 | 团体预约的同行人，只需 `name`（必填）+ `phone`（选填）；`mateMode=1` 时仍必须带 `idCard` |
| `wxOpenid` | 否 | 微信小程序一键登录返回的 openid；传了就在建单后绑定到访客档案 |
| `startDate` | 是 | 不早于今天，不超过 30 天后（BR-P-004） |
| `visitor.idCard` | **否（选填）** | 填了就校验校验位 + 黑名单 + 未在预约中；不填仍可预约（后续通行走人脸/二维码）。V20 起 `visitor.id_card_*` 允许为 NULL |
| `mates[].idCard` | 条件 | `mateMode=1` 时必填（BR-P-023） |
| `mateMode` | 是 | 0 随行 / 1 各自刷证 |
| `gateScope` | 否 | 1 指定门点 / 2 全部门点（默认按前端传值）；为 2 时忽略 `gateIds`（C-64） |
| `gateIds` | 否 | 申请的门点集合；必须都启用且不是「待分配」 |
| `gateId` | 否 | 兼容字段（单个门点）；与 `gateIds` 同时传时以 `gateIds` 为准 |

  "code": 0,

### 3.3 审批动作

> **2026-11-21 起为单级审批（C-70）**：员工不再登录审批，
> `/api/app/approval/**`（员工端 pass/reject/transfer/countersign/remind/todo）**已删除**，
> 统一改用管理端接口 `/api/guard/approval/**`（见 §5.4）。

| 方法 | 路径 | 请求体 | 说明 |
|---|---|---|---|
| GET | `/api/guard/approval/todo` | `?page=&size=` | 待审核列表（当前账号拥有的任一角色 + 会签指派给本人的任务；每行带 `nodeName` 当前节点） |
| GET | `/api/guard/approval/{taskId}` | — | 审核详情（含访客申请门点、`qrRequested`/`qrApproved`、`nodeName`、`allowEditGates`、`allowQr`） |
| POST | `/api/guard/approval/{taskId}/pass` | `{"comment":"","approvedGateIds":[6,7],"qrApproved":true}` | **本节点通过**。会签未齐→等待；有下一节点→生成下一节点任务；末级通过→下发门禁授权。`approvedGateIds`/`qrApproved` 在该节点不允许时被忽略 |

```json
{
  "code": 0,
  "data": {
    "appointmentNo": "A2026111700001",
    "status": 30,
    "needSecondLevel": false,
    "dispatchStarted": true
  }
}
```

**服务端事务边界**：

```
1. 校验 task.status=1、assignee_type=2 且 assignee_role ∈ 当前账号角色（否则 3005/3006）
2. 写 approval_action（记 operator_type=2 与本次批准门点快照）
3. approvedGateIds 非空时覆盖批准集合（申请集合保持不动，便于留痕对比）
4. qrApproved 非空时落 qr_approved / qr_approved_by / qr_approved_at
5. 单级：预约单 → 30（已通过），事务提交后发事件 → 异步授权签发 + 下发
```

> **二级由保安在 `/api/guard/approval/**` 处理**：保安是后台账号（sys_user + GUARD），
> 任务是角色任务而非指定到人——保安轮班，谁值班谁复核。

> 下发**不在审批事务内**，避免设备超时拖长事务；失败由 `device_cmd` 重试 + 对账兜底。

**授权签发内部规则（非 HTTP，供实现参考）**：

```
预约单进入 APPROVED(30)
  → 取批准门点集合（appointment_gate.stage=2；「全部门点」在此快照）
  → 计算 validFrom = 预约日 00:00:00
          validTo   = 预约日 23:59:59        （C-60 / BR-V-007）
  → 按批准门点**每个门点生成一条** access_grant(status=2 待下发)（C-64）
      personNo = visitor.person_no
  → 若 mateMode=1，为每个有身份证的同行人也生成一组
  → 生成 1 个 sync_batch + 覆盖所有批准门点下设备的 sync_batch_item
  → 某门点暂时没有设备：跳过该门点设备，不阻塞其他门点（授权仍是 ACTIVE，
    设备装机后由对账 expectedOn(gate) 自动补齐名单）
  → 全部 ack 后：所有 access_grant.status=1，预约单 → GRANTED(35)，推送"可通行"通知
  → 任一台失败：全部保持 30（授权置 2 待下发），重试；超 3 次告警
```

| 规则 | 实现 |

| BR-V-021 同行人随行 | 核验事件带预约单号，同行人放行由设备/保安按开关处理（设备侧待联调） |
| BR-V-022 必须在线校验 | 保安端与设备端都走平台接口，无本地缓存 |
| BR-V-024 失败留痕并区分原因 | 写 `access_event`（`source=4`），`fail_reason` 区分无效/过期/已撤销/无授权/不在时段/门点不符 |
| 只存码摘要 | `qr_ticket.code_hash = SHA256(code)`，DB 无明文码 |
| 签发前提 | 预约必须有**生效授权**且在授权时段，否则 `3011` / `3010` |

> 设备侧扫码走 `/openapi/v1/qrCodePush`（平台判定，含票据校验）；九鼎的 `/compare/online` 已下线）；
> 换新机验证 `QR_ONLINE` 能力后，把 `qr_ticket` 的撤销/次数校验接进 `OnlineCompareService` 即可，接口不变。

### 5.11 门点管理（多门点部署必需）

> 厂区多门点时，预约授权、设备归属、通行记录、报表都按门点区分。
> 「待分配」是系统保留门点（`gate_type=9`），不参与授权、不能停用。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/gate` | 门点列表（含 `deviceCount`、`unassigned` 标记） |
| GET | `/api/admin/gate/{id}` | 门点详情 |
| POST | `/api/admin/gate` | 新增：`{gateCode, gateName, gateType, sortNo, remark}` |
| PUT | `/api/admin/gate/{id}` | 修改名称/类型/排序/备注（编码建好不再改） |
| PUT | `/api/admin/gate/{id}/status` | 启用停用：`{status: 0 停用 / 1 启用}` |

门点列表项：

```json
{
  "id": 3,
  "gateCode": "EAST_GATE",
  "gateName": "东门",
  "gateType": 2,
  "gateTypeText": "侧门",
  "status": 1,
  "statusText": "启用",
  "sortNo": 1,
  "remark": "访客主通道",
  "unassigned": false,
  "deviceCount": 1
}
```

| 校验 | 说明 |
|---|---|
| 编码 | 大写字母/数字/下划线，≤32 位，全局唯一；`UNASSIGNED` 是保留编码 |
| 类型 | 1 大门 / 2 侧门 / 3 车库门（9 待分配仅系统内部使用） |
| 停用 | 门点下**还有启用设备**时拒绝停用（3004），必须先把设备移到别的门 |
| 待分配 | 不能改成普通门点、不能停用 |

> 访客端选门：`GET /api/app/gate`（公开接口，未登录也可调），只返回启用且非「待分配」的门点。

### 5.13 通行记录（行人 + 车辆合并，C-69）

> 管理端「通行记录」页只保留**这一套接口**：一人一天一行，行人（`access_event`）与车辆
> （`vehicle_event`）合并展示。§5.12 的车辆原始查询保留作排障用途。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/traffic/summary?from=&to=&personType=&deptId=&channel=&keyword=&page=&size=` | 按「人员编号 + 日期」分组的汇总 |
| GET | `/api/admin/traffic/{personNo}/detail?date=` | 某人某天的全部进出明细 |

**summary 返回**（一行 = 某人某天）：

```json
{
  "personNo": "V202611190002",
  "personName": "李小红",
  "personType": "VISITOR",
  "personTypeText": "访客",
  "day": "2026-11-19",
  "firstIn": "2026-11-19 09:15:00",
  "lastOut": "2026-11-19 17:30:00",
  "inCount": 2,
  "outCount": 1,
  "totalCount": 3,
  "channelText": "车辆+行人",
  "deptName": ""
}
```

| 参数 | 取值 | 说明 |
|---|---|---|
| `personType` | `EMPLOYEE` / `VISITOR` | 人员类型筛选（按 `person_no` 前缀 `E`/`V` 判定） |
| `deptId` | 部门 ID | 部门筛选（只对员工生效；访客无部门） |
| `channel` | `PEDESTRIAN` / `VEHICLE` | 通行方式筛选 |
| `from` / `to` | 日期 | 不传默认近 7 天（含今天） |
| `keyword` | 文本 | 匹配姓名或人员编号 |

> 只统计**成功**记录（`result_status=1`）；被拒绝的尝试仍可在原始记录里查。
> `firstIn` = 当天最早的进场时间，`lastOut` = 当天最晚的出场时间，没有则为空。

**detail 返回**（每条 = 一次进出，带方式与点位）：

```json
{
  "personNo": "V202611190002",
  "personName": "李小红",
  "date": "2026-11-19",
  "records": [
    { "eventTime": "2026-11-19 09:15:00", "channel": "PEDESTRIAN", "channelText": "行人",
      "direction": 1, "directionText": "进", "methodText": "人脸", "plateNo": "",
      "gateName": "东门", "deviceName": "东门人脸终端", "eventId": 12 },
    { "eventTime": "2026-11-19 16:40:00", "channel": "VEHICLE", "channelText": "车辆",
      "direction": 1, "directionText": "进", "methodText": "车牌识别", "plateNo": "京B12345",
      "gateName": "东门", "deviceName": "", "eventId": null }
  ]
}
```

**detail 里的人员档案**（筛选与追溯用）：

| 字段 | 员工 | 访客 |
|---|---|---|
| `personType` / `personTypeText` | `EMPLOYEE` / 员工 | `VISITOR` / 访客 |
| `deptName` | ✅ 所属部门（部门筛选依据） | — |
| `empNo` / `title` / `statusText` | ✅ 工号、职务、状态 | — |
| `validFrom` / `validTo` | ✅ 证件有效期（无到期显示"长期"） | — |
| `company` / `faceStatus` | — | ✅ 单位、人脸采集状态 |
| `phoneMask` / `plateNo` | ✅ 脱敏手机、车牌 | ✅ 脱敏手机 |
| `appointments` | — | ✅ **当天申请信息 + 审批轨迹**（见下） |

**访客 `appointments[]` 结构**：

```json
{
  "appointmentNo": "A2026111900002",
  "status": 70,
  "statusText": "已过期",
  "purpose": "商务洽谈（东门）",
  "visitorType": "商务",
  "visitEmployeeName": "张三",
  "approvedGates": "东门",
  "plateNo": "京B12345",
  "startTime": "2026-11-19 08:00:00",
  "endTime": "2026-11-19 20:00:00",
  "createdAt": "2026-11-19 11:37:32",
  "actions": [
    { "action": 1, "actionText": "通过", "operatorType": 1, "operatorRole": "被访人",
      "operatorName": "张三", "comment": "同意，从东门进", "gates": ["东门"],
      "at": "2026-11-19 11:37:32" }
  ]
}
```

> `operatorType`：1 = 被访员工（App 确认），2 = 后台账号（门卫复核）。
> `actions` 直接取 `approval_action`，`gates` 由 `gate_snapshot` 还原成门点名。
| 识别方式 `methodText` | 来源 |
|---|---|
| 人脸 / 身份证 / IC 卡 / 二维码 / 密码 / 人工开门 | `access_event.identify_type` |
| 车牌识别 | `vehicle_event`（固定） |

> `eventId` 非空时可调 `/api/admin/access/event/{eventId}/media` 看抓拍照片。

## 7. 版本与兼容
