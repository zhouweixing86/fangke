## 2. 与本项目的冲突 / 风险（部署前必须逐条定）

| # | 事项 | 影响 | 建议 |
|---|---|---|---|
| 1 | **8080 被 pinDouServer 占用** | 本项目后端默认 `SERVER_PORT=8080`，直接起会端口冲突 | 本项目改用 **8081**（或独立域名 + 反代），systemd 服务名独立为 `fangke-visitor` |
| 2 | **内存只有 1.8 GB**，靠 swap 撑，余量常年 ~250 MB | 再加一个 Spring Boot（默认堆按物理内存推算）+ MinIO 极易 OOM，连带影响现有 pinDouServer | JVM 必须限死：`-Xmx256m -Xms128m -XX:MaxMetaspaceSize=160m -XX:+UseSerialGC`；**建议停掉 openGauss 容器**（省 1.5 GB 限额）或换 4 GB 机器 |
| 3 | **没有 S3 / MinIO** | 员工人脸、访客采集人脸、抓拍图全部不可用（`S3StorageService` 会降级告警，其余功能正常） | 三选一：①**阿里云 OSS（推荐，不占本机内存）**；②本机装 MinIO（约 +150 MB 内存）；③先降级，只跑「刷证/二维码」 |
| 4 | MySQL 是 **5.7.40**（2026-11-20 实测），已 EOL，且与 pinDouServer 共用同一实例 | 本项目设计按 8.0；已扫描 V1–V18 迁移脚本：**无 8.0 专属语法**（无 `utf8mb4_0900`、无窗口函数、无 CHECK/GENERATED、无 RENAME COLUMN），JSON 列 5.7.8+ 支持 → 5.7 **理论可跑** | 建**独立库** `fangke` + 独立账号（不要用 root），字符集 `utf8mb4 / utf8mb4_general_ci`；跑一次全量 Flyway 验证；长期建议单独起 MySQL 8 容器（约 +300 MB 内存），**不要升级现有实例**（pinDouServer 在用它） |
| 5 | 3306 监听 `*`，可能对公网开放 | 数据库裸奔 | 改 `bind-address=127.0.0.1`，或确认安全组未放行 3306 |
| 6 | 时区 | 服务器与项目不一致会让预约时间、通行记录整体偏 8 小时 | `timedatectl set-timezone Asia/Shanghai`，JVM 加 `-Duser.timezone=Asia/Shanghai` |
| 7 | **设备连通性（最关键）** | 真机是厂区局域网里的 PULL 终端，要主动访问 `/openapi/v1/**`。平台在阿里云公网，厂区通常没有固定公网出口 → **设备连不上平台，名单下发和通行记录全断** | 见 §3 方案对比，**建议 A** |
| 8 | 域名 / HTTPS | 微信小程序、正式 APP 必须 **备案域名 + HTTPS**，当前只有公网 IP | 先确认是否有可用域名与证书；没有则 H5 先跑 IP，小程序上线前补齐 |
| 9 | 生产密钥全是开发默认值 | `CRYPTO_AES_KEY`、`CRYPTO_HMAC_KEY`、`JWT_SECRET`、`QR_SECRET`、`DEVICE_PULL_SIGN_KEY` 都是 `dev-only-*` | 全部换成随机强密钥（AES/HMAC 两把必须不同），并在上线后**不再变更**（变更会导致既有密文无法解密） |
| 10 | 短信验证码是 mock | `APP_SMS_MOCK` 默认 `true`，验证码直接回显在接口里 | 生产必须 `false` + 接短信网关，否则任何人可登录任意手机号 |
| 11 | 磁盘 17 GB 且日志无轮转 | 运行日志 + 备份会吃盘 | logback 按天滚动保留 30 天；MySQL 每日备份到 `/www/backup` 并定期清理 |
| 12 | 安全加固 | root 密码登录开着、5432 对 `0.0.0.0/0` 开放、`/tmp/omis-dl` 公网可下载 | 关 `PasswordAuthentication`、收紧安全组、删除中转配置与残留文件 |

## 3. 设备连通性方案（必须先定，决定部署位置）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 后端部署到厂区本地**（推荐） | 厂区放一台小主机/NAS（4 核 8 GB）跑本系统，设备直连内网 IP | 零延迟、断网也能用、照片可存本地 | 需要一台本地机器 + 现场运维 |
| B. 厂区出口端口映射 | 厂区路由器把 `http://<公网IP>:8081` 映射到内网后端 | 现在这台阿里云就能用 | 需要固定公网 IP/DDNS，暴露面变大，必须上 HTTPS + 签名 |
| C. SD-WAN / VPN | 阿里云与厂区打通内网 | 体验接近 A，集中运维 | 有成本，依赖网络设备 |

> 当前设备协议是**设备主动轮询**（`/openapi/v1/heartBeat` 等 13 个端点），所以**必须设备能访问到平台**，平台无法主动连设备。

## 4. 建议部署拓扑（若最终仍用这台阿里云）

```
nginx(80/443)
  ├─ /            → 静态文件：web/dist（管理端）
  ├─ /m/          → 静态文件：uniapp H5 构建产物
  ├─ /api/        → 127.0.0.1:8081
  └─ /openapi/    → 127.0.0.1:8081（设备轮询入口）
系统服务：
  fangke-visitor.service  → java -jar /www/wwwroot/fangke/visitor-server.jar
数据库：
  MySQL 127.0.0.1:3306 / fangke（utf8mb4）
对象存储：
  阿里云 OSS（bucket 私有 + 预签名 URL）或本机 MinIO
```

## 5. 生产环境变量清单（对照 `application.yml`）

| 变量 | 生产值要求 |
|---|---|
| `SERVER_PORT` | `8081`（避让 pinDouServer） |
| `DB_HOST` / `DB_PORT` / `DB_NAME` | `127.0.0.1` / `3306` / `fangke` |
| `DB_USER` / `DB_PASSWORD` | 独立账号 `fangke_app` + 强密码 |
| `S3_ENDPOINT` / `S3_BUCKET` / `S3_REGION` | OSS 的 `https://oss-cn-xxx.aliyuncs.com` / `fangke` / 对应 region |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | OSS RAM 子账号 AK/SK（只授权该 bucket） |
| `CRYPTO_AES_KEY` / `CRYPTO_HMAC_KEY` | 两把不同的 32+ 位随机串，**上线后不再改** |
| `JWT_SECRET` | 32+ 位随机串 |
| `QR_SECRET` | 32+ 位随机串 |
| `DEVICE_PULL_SIGN_KEY` | 与设备端约定后填入；`DEVICE_PULL_VERIFY_SIGN=true` |
| `DEVICE_PULL_PUBLIC_BASE_URL` | 设备可达的地址（决定二维码推送 `thirdQrUrl`，留空则不下发） |
| `DEVICE_PULL_HEART_SECONDS` | 默认 30 |
| `APP_SMS_MOCK` | **false**（并接入短信网关） |
| `APP_ALLOW_EMPLOYEE_HEADER` | **false** |
| `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` | 首次启动建管理员，登录后立刻改密 |

## 6. 上线前 Checklist

- [ ] MySQL 版本 ≥ 8.0，建库建号（utf8mb4），`flyway_schema_history` 从 V1 跑到 V18 无报错
- [ ] 服务器时区 `Asia/Shanghai`，JVM `-Duser.timezone=Asia/Shanghai`
- [ ] JVM 内存参数按 §2-2 限死，压测一次 20 并发登录/查通行记录不 OOM
- [ ] 对象存储可用：上传员工照片 → 设备名单能取到图；不可用则明确告知「照片功能降级」
- [ ] systemd 单元 + 开机自启 + 日志轮转
- [ ] nginx：静态缓存、`/api` 与 `/openapi` 反代、gzip、上传大小 10 MB
- [ ] 若走公网：域名 + HTTPS（小程序强制）
- [ ] 设备端 heartbeat 地址指向平台，`verifySign` 开关与平台一致，心跳后 `person_count` 有值
- [ ] 生产密钥全部替换，`.env` 权限 600，不入库
- [ ] 备份：MySQL 每日全量 + OSS 生命周期；恢复演练一次
- [ ] 安全：关 root 密码登录、3306 只听本机、收紧 5432、清理 `/tmp/omis-dl`

## 8. 变更记录（服务器侧操作）

### 2026-11-20

| 操作 | 命令 / 文件 | 结果 | 回滚方式 |
|---|---|---|---|
| 停用 openGauss | `docker stop opengauss` | 5432 不再监听；容器 `Exited (0)`，`restart=unless-stopped` 表示手动停后 docker 重启也不会自动拉起 | `docker start opengauss` |
| 下线「员工数字画像」演示站 | `shuzihua-demo.conf` 备份并移出到 `/root/ops-backup-20261120/shuzihua-demo.conf.removed` | 公网 `http://<IP>/` 从 200 变 **444**（本机 curl 实测 exit 52） | 移回 conf + 删 `0.default-deny.conf` + `nginx -t && /etc/init.d/nginx reload` |
| 新增 80 默认拒绝 | `/www/server/panel/vhost/nginx/0.default-deny.conf`（`listen 80 default_server; return 444;`） | 避免站点移除后 IP 直连落到 `java_pinDouServer-0`（其 `root /www/wwwroot`，会把 jar 暴露出去） | 删除该文件后 reload |

**未受影响（已实测）**：OMIS 中转 `Host: omis-dl-tmp.local` → 200；`127.0.0.1:8080` pinDouServer → 404（进程正常）；宝塔 8888 / 888 正常。

**资源变化**：内存 available 1001 MB → **1054 MB**，swap 693 MB → **638 MB**（约省 160 MB）。

**80 端口剩余站点**：`omis-dl-tmp.local`（797 MB 中转，建议清理）、`47.103.158.156`（pinDouServer，IP 疑似写错）、`phpfpm_status.conf` 里的 `server_name 127.0.0.1`（宝塔自带，返回「没有找到站点」占位页）。
